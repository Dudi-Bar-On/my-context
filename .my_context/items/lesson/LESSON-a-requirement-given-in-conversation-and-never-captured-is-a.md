# a requirement given in conversation and never captured is a requirement that does not exist

Found 2026-08-25. The owner said: "i have added a requirement long time ago about browsing and viewing markdown files rendered - do not remember where it should apear in which menu item but i do remember the request".

It was searched for properly -- every requirement, rule and task in the corpus, all seven design specs, the plans, and the mockup s twenty-one sections. IT IS NOWHERE. The closest match is a File browser the spec explicitly MERGED into the coverage map s detail pane, which answers what governs a file and never shows the file.

So the requirement was real, was given, and never reached the record. Months of work were planned around a corpus that did not contain it, and it surfaced only because a screen walkthrough happened to reach the one screen that renders markdown.

THIS IS THE FAILURE THE PROJECT EXISTS TO END, occurring inside the project. INSTR-a-ruling-taken-in-the-screen-walkthrough-is-captured-before-the-next-screen was written the day before this, for exactly this reason, and it is scoped to the walkthrough. The general form is larger: any requirement the owner states in conversation is captured in that turn, or it is not a requirement -- it is a memory, and memories do not survive a compaction, an agent handoff, or four months.

WHAT MADE IT RECOVERABLE AT ALL: the owner remembered. That is not a mechanism.
