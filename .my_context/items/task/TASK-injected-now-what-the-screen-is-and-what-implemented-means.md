# Injected now: what the screen is, and what implemented means for it

WHAT THE SCREEN IS, so it can be built without opening the mockup. nav.inj -- Injected now, section data-p="injected". What the selected session has ACTUALLY been given, read from the seen file rather than from the ledger's replayed projection, which nothing here updates and which would show a different number. Three columns -- item, tier, when -- straight off a line of that file, and no fourth: no join invents a column, and the title the response once carried was cut after a repo-wide search found no reader of it. ONE ROW PER DELIVERY, in the file's own order, nothing sorted, grouped or collapsed: a second delivery of an item is a second row, and an item the corpus no longer holds keeps its row, because the injection still happened. It disagrees with the sessions endpoint's count on three axes -- items against deliveries, a carried tier the ledger has no slot for, and a cleared window that removes the seen file while keeping every ledger row -- and neither surface is wrong on any of them.

WHAT IMPLEMENTED MEANS: three columns off the seen file and nothing joined in; THREE distinguishable zero states, not two -- a file that was read and held nothing, a file that does not exist, and a session with nothing yet -- because a missing file and an empty one used to answer in identical bytes and the screen said something false about seven sessions; and an unreadable file drawing its error and NEITHER zero sentence, since two explanations of one absence is worse than none.
