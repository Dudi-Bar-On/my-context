# Coverage gaps: gaps.cat is a literal, so fifteen empty categories can never be named

WHAT THE SCREEN IS, so it can be built without opening the mockup. `nav.inj` - **Coverage gaps**, `<section data-p="gaps">`. A SCREEN OF ITS OWN, not a panel on the coverage map: its own rail entry (`s.gaps`), its own section, and its own three-column table - Where / What / Next (`th.where`, `th.what`, `th.act`). The plan's Step 3 folds it into `coverage.js` as two trailing paragraphs on two keys no table declares; the design of record gives it a screen, and folding it back would drop one.

ITS SUBJECT IS A NEGATIVE, WHICH IS WHY IT CANNOT BE A LISTING. `gaps.v` in its own words: "names what is missing, which no listing can". The directory rows come from the same `/api/coverage` answer the coverage tree is built from, through `coverageGapRows`, and they name the SHALLOWEST directory nothing scopes - once, never its whole subtree.

THE MOCKUP'S TABLE HAS THREE ROW SHAPES. One is served and drawn. The other two are not, for two different reasons, and one of them is a ONE-WORD FIX in the design of record.

**THE EMPTY-CATEGORY ROWS - `gaps.cat` + `gaps.r3`, "category `open_question` - empty". THIS IS THE TASK.** The data is served and this screen fetches none of it. `/api/help/categories` answers `corpus.empty`, and it was measured on 2026-08-23 by calling `apiHelp` directly: SIXTEEN empty categories over `.demo-corpus` and FIFTEEN over this project's own corpus, `open_question` among them both. The screen draws none, because THE STRING CANNOT CARRY THEM. `gaps.cat` is `category {m:open_question}` in English and the same `{m:open_question}` inside the Hebrew, and an `{m:...}` run is a LITERAL - `strings/en.js`' own grammar block says so, and `strings-parity.test.ts` holds the two payloads identical for exactly that reason. So the key can name ONE category, the one the mockup's demo row happens to show, and there is no substitution for the other fourteen.

DO NOT WORK AROUND IT BY DRAWING THE BARE NAME. Putting the category name alone in the Where cell loses the word that tells a category apart from a directory, which is the whole content of that cell - and this screen's rows are directories and categories side by side, so that word is the only thing distinguishing them.

THE FIX IS ONE WORD, IN THE DESIGN OF RECORD FIRST: `gaps.cat` written as **`category {mv:name}`** - the value-slot form the tables already use for ids, paths and globs. Then both tables are regenerated by machine, and `corpus.empty` fills the rows with no further work at all. NOTHING BLOCKS THIS BUT THE MOCKUP EDIT: `plan:rulings seq:12` put `{mv:name}` into the grammar and `seq:15` regenerated the tables, and both are done. It belongs in the same one mockup session as `plan:screens seq:10s` and `plan:walk seq:20`, because the mockup is the owner's file.

**THE "NOT EXAMINED" ROW - `cov.k4` + `gaps.r2`, "`vendor/` - not examined - past the file limit". NOT THIS TASK, and it is already owned.** It names a PATH and no endpoint carries one: `/api/coverage` answers a single global `truncated` boolean, and the read model records the ask in its own words - it needs the paths `listRepoFiles` did not reach. That is `plan:ui1 seq:17e` and it stays there. What IS served is the boolean, and this screen now says it, as a `p.small` under the table rather than as a row - the same treatment `screens/coverage.js` gives the identical fact with the identical two keys. A row saying "not examined" with no Where would be the third state folded into nothing, which `gaps.note` forbids outright.

AND THE CELL KINDS FOLLOW FROM THIS, WHICH IS WHY THE TWO MOVE TOGETHER. `plan:screens seq:4s` is down to six missing kinds after the table landed - `button.icon`, `span.m`, `span.v`, `td`, `td.m`, `td.small` - and five of the six are the cells of the rows this task unblocks. `e2e/screen-parity.spec.ts`' `KNOWN_GAPS` ledger may only SHRINK and the gate fails if a listed gap is no longer missing, so delete `gaps`' closed entries in the same change.
