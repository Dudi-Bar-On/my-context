# the checked-in tutorial manifest is proved to be what the generator derives

FOUND 2026-09-08 while closing `plan:archive seq:6` (the archive tutorial).

WHAT WAS TRUE AT HEAD. `npm run gen:tutorials` could not run at all. `validateCoverage` threw on
FOUR names, not the two the archive item predicted:

    CLI command "conversation.ts": claimed by 0 tutorials (none)
    CLI command "handover.ts":     claimed by 0 tutorials (none)
    UI screen  "conversations.js": claimed by 0 tutorials (none)
    slash command "handover.md":   claimed by 0 tutorials (none)

`conversation.ts` and `conversations.js` were the known, filed red. `handover.ts` and `handover.md`
were not: they were ALREADY IN `docs/tutorials/manifest.json`, under `sessions-and-continuity`, and
were NOT in the generator's `CLUSTERS` table. They arrived in `bd249ec` (2026-09-06), where the
roster was carried forward without the table that is supposed to produce it.

SO THE CHECKED-IN ROSTER WAS NOT REPRODUCIBLE, AND NOTHING SAID SO. `test/core/tutorial-manifest.test.ts`
read the manifest and passed on `handover.md`, because the manifest claimed it. The only surface that
disagreed was the generator, and a generator nobody runs reports nothing. The test's own header argues
for its INDEPENDENCE from the generator and that argument is right — but independence from the
generator is not the same as a proof that the generator still produces the file.

WHAT IS MISSING, AND IT IS ONE ASSERTION. `deriveTutorialManifest(REPO_ROOT)` against the parsed
`docs/tutorials/manifest.json`, deep-equal. It cannot be added to `test/core/tutorial-manifest.test.ts`
without giving that file the import its header refuses; the honest shape is a SECOND test whose subject
IS the reproducibility, stating in its own header that it is deliberately the coupled half and that
the coverage tests beside it stay uncoupled.

WHY IT MATTERS BEYOND TIDINESS. `STD-documentation-is-regenerated-not-edited-to-match` is the standing
rule for exactly this file, and the defect it forbids ran for two days undetected. The failure is also
SILENT IN THE DIRECTION THAT COSTS: a roster edited by hand to claim a surface no tutorial teaches is
a false coverage claim, and the roster exists to prevent precisely that.

NOT FIXED HERE. The four names above were repaired in `CLUSTERS` and the manifest regenerated by the
archive-tutorial lane (`plan:archive seq:6`), which owned `scripts/build-tutorial-manifest.ts` but not
`test/`. Seven of seven in `test/core/tutorial-manifest.test.ts` are green now. What is not built is the
gate that would have caught it on the day.
