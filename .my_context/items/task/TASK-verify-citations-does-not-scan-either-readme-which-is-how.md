# verify:citations does not scan either README, which is how six false claims sat there

Found 2026-08-24 by the documentation wave, and it explains the pattern rather than just adding to it.

`scripts/verify-citations.ts` walks `docs/superpowers/specs`, `docs/superpowers/plans` and `docs/design`. It does NOT walk `README.md` or `docs/README.he.md` - the two documents a person actually reads first.

WHAT THAT COST, measured in one pass: six claims were false or missing, including "the server exits after fifteen idle minutes" when `IDLE_MS` is eight hours, and "the served page is an empty shell" when 22 screens ship. Both had been true once. Neither was cited, so neither could be caught - and a README that denies a shipped feature is worse than one that omits it, because a reader stops looking.

THE CATCH, and it is why this is not a one-line change: the READMEs are largely GENERATED by `npm run gen:docs`, and generated prose does not carry citations. So scanning them would check the hand-written parts and say nothing about the rest. The honest fix may be to cite the hand-written claims deliberately rather than to widen the walk and declare victory.

ALSO FOUND: `docs/README.he.md` is missing `/mycontext:focus`, which the English has. `parity.test.ts` compares heading depth and structure and is structurally blind to a missing list entry - by design, and worth knowing about.
