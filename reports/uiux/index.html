mycontext v2.0 — UI/UX panel

Nine experts, run 2026-08-19. Seven produced a working sketch.

Historical — this panel ran on 2026-08-19. These sketches record the design as of that date and are not synced forward. They are kept, and still worth reading, because their reasoning is what the mockup and the app were drawn from. Where a sketch and docs/design/web-ui-mockup.html differ, the mockup is current.
Read these as proposals, not decisions. Nothing here has been filtered, reconciled or checked against the spec yet — several sketches contradict each other, and at least one proposes replacing a structure another argues to keep. They are also sketches: inline styles and scripts are fine here and forbidden in the real app, whose CSP is default-src 'none'.

02 · information architecture

Three groups, not four — and an item pane

Argues the current Core / Work / Watch / Report names the build rather than the user, and replaces it with Injection / Evidence / Change.

There is no item page. Sixteen screens name item ids and give them nowhere to go. 16 destinations → 8, with no capability lost.

03 · interaction design

Compose-and-copy, with a receipt

The UI never writes; every mutation is a command you paste. This makes that feel like control rather than a workaround.

The composed command becomes an object with six states, a preview before and a receipt after — the audit record, where origin:'human' proves it was your shell.

04 · visual design

Evolve, don't replace

Argues against a bolder redesign: paper-and-gold is the right material metaphor for a tool that renders verdicts. The weakness is system discipline, not palette.

Map visual weight to epistemic status — measured numbers render large, fabricated ones stay small and tagged.

05 · data visualisation

Seven graphics, no library

Hand-written SVG only. Live RTL toggle and a 50 ↔ 57,195-file scale toggle.

Hoist pinned out of the coverage tree. always:true items govern every path, so colouring them per-path is why a governed directory renders as a gap.

06 · accessibility & RTL

What the current mockup breaks

Audited the regenerated mockup and found five measured contrast failures and two whole missing interaction models.

The Hebrew table uses innerHTML, destroying the bidi isolation the CSS provides — English isolated, Hebrew not. Gold vs green measures 1.04:1.

The URL is the store

How sixteen screens share state with no framework and no store library, under default-src 'none'.
