# Accessibility and internationalisation — v2.0 web UI

**Audited:** `docs/design/web-ui-mockup.html` (802 lines, regenerated 2026-08-19).
**Against:** `2026-08-16-web-ui-design.md` §3 *"English and Hebrew, structurally mirrored"* and §9;
`2026-08-18-v2-decisions.md`.
**Sketch:** `sketches/06-a11y.html` — runnable, zero-dependency, demonstrates the bidi contract,
an ARIA tree, table semantics and a batched live region.

Everything numeric below was measured, not estimated. Contrast ratios come from a WCAG 2.x
relative-luminance script run over the mockup's own `light-dark()` token pairs; the `Intl`
behaviours were executed on Node 24.14. Presence/absence claims come from `grep` over the file,
and the counts are quoted. This project's recorded characteristic defect is *asserting a property
the code does not have*, so nothing here is asserted from reading alone.

**One thing to say first, because it governs how the rest reads.** The stylesheet is the best RTL
work I have seen in a hand-written sheet: `grep` for `margin-left|margin-right|padding-left|
padding-right|text-align:left|text-align:right|border-left|border-right|^left:|^right:` returns
**zero matches** in 802 lines. The `.m,code,kbd{direction:ltr;unicode-bidi:isolate}` rule is
correct and the comment above it understands why. The `[dir="rtl"]` `box-shadow` mirror is the one
exception handled the one way it can be. The visual panelist's conclusion that *"RTL is nearly
solved already"* is right **about the CSS layer** — and that is the trap, because the layer that
breaks is the one below it. The Hebrew string table throws away every isolation the CSS provides,
and the mechanism is three lines of `applyLang()`.

## Findings in the current mockup

Ranked. Severity is: **Critical** = an entire audience cannot use the feature; **High** = a
normative WCAG 2.2 AA failure or an unusable path with a workaround; **Medium** = a real defect
with a partial workaround; **Low** = correctness/robustness.

### 1. The Hebrew string table destroys the bidi isolation the CSS provides — **Critical**

The English DOM wraps every technical term in `<span class="m">`, which is what earns the
`direction:ltr; unicode-bidi:isolate` rule. `applyLang()` then does this:

```js
$$('[data-t]').forEach(el=>{ const v=TABLE[el.dataset.t]; if(v!==undefined) el.innerHTML=v; ... });
```

It replaces the whole subtree — **including the `.m` spans** — with a flat Hebrew string. And the
Hebrew strings carry the technical runs as bare text. Measured over the parsed table: **10 of the
114 Hebrew values contain a bare Latin run.** Seven are the identifier class:

| Key | Unisolated run inside Hebrew prose |
|---|---|
| `cov.sub` | `matchesScope`, `injection()` |
| `cfg.sub` | `resolveConfig` |
| `cfg.nowfits` | `src/billing/**` |
| `sim.note` | `itemCost` |
| `inj.note` | `Ledger.seen` |
| `preview.inputs` | `event, path, seen, restore` + `focus` |
| `ask.why` | `readOnly:true`, `VACUUM INTO` |

The other three are `ask.v` (`SQL`), `preview.r1` (`jit`) and `strip.append` (`p95`) — same class,
lower stakes.

The isolation lives in the markup and the translation replaces the markup. So in English every id
is isolated and in Hebrew none of them are — which is the exact opposite of where isolation is
needed. `grep -c "<bdi"` → **0**; `grep -n 'dir="'` in markup → **1 match, and it is a CSS
selector**. What this renders is specified in *Bidi rules* below; `injection()` is the sharpest
case, because bidi rule N2 gives the parentheses the paragraph direction, which mirrors their
glyphs and moves them to the other side of the identifier.

**Fix:** values carry named placeholders and never markup; the renderer substitutes *nodes*
(`fill()` in the sketch). This removes `innerHTML` from the renderer at the same time, which
finding 21 needs anyway.

### 2. Both popovers are keyboard-unreachable and screen-reader-invalid — **Critical**

`#sesspop` and `#focuspop` are the session selector and the focus control — spec §3's contract,
and §9's pinned decisions 5 and 7. Every one of the following is a separate defect:

- Rows are `<div role="option">` with **no `role="listbox"` ancestor**. An orphan `option` is
  dropped or mis-mapped by every screen reader; `aria-selected` on it means nothing.
- Rows have **no `tabindex`** (`grep -c tabindex` → **0** in the whole file). Tab cannot reach
  them, and there is no arrow-key handler. The session picker is mouse-only.
- The triggers carry `aria-haspopup="true"`, which is `menu` — the popup is not a menu.
- There is **no `aria-expanded`** (`grep -c` → 0), so the collapsed/expanded state is invisible.
- There is **no Escape handler**. `document.addEventListener('click', …)` is the only dismissal.
- Focus is neither moved in nor returned on close.

### 3. The coverage tree has no tree semantics and no expand/collapse — **Critical**

```html
<button data-f="src/billing/prices.js" aria-pressed="true"><span class="dot g"></span>&nbsp;&nbsp;&nbsp;&nbsp;prices.js</button>
```

Depth is **four non-breaking spaces**. A screen reader announces "button, prices.js" with no
level, no parent, no sibling count — the hierarchy that is the entire point of the screen is
invisible. There is no `role="tree"`, no `aria-level`/`aria-setsize`/`aria-posinset`, and **no
expand/collapse exists at all**, in a screen the spec expects to render a whole repository.
`aria-pressed` models single selection as nine independent toggles. Nine tab stops for nine rows
does not scale to a real tree.

### 4. Nothing on the page is a live region — **Critical**

`grep -c 'aria-live\|role="status"\|role="alert"'` → **0**. Three separate things change silently:

- **The audit stream.** `renderAudit()` sets `$('#atbl').innerHTML = …` — a full re-render on
  every filter change and (in the real app) every arriving record. Wholesale replacement makes
  some screen readers re-announce the entire table and destroys the reading cursor and any focus
  inside it.
- **The server-exited banner.** `$('#exited').hidden = false` after 40 heartbeats. A blind user is
  never told the page has stopped being live — while every number on screen silently becomes
  historical.
- **The context figure.** `#ctx` cycles three states including *"context not yet known"*.

### 5. The shell cannot reflow — **Critical** (WCAG 1.4.10)

```css
body{ … overflow:hidden}
.app{ … grid-template-columns:212px 1fr;block-size:100vh}
```

`overflow:hidden` on `body` means content that does not fit is **unreachable**, not scrolled. At
320 CSS px the fixed 212px rail leaves 108px of body. The only responsive rule in the file is
`@media (max-width:860px){.two{grid-template-columns:1fr}}` — a viewport query, so it does not
fire under text-only zoom. `block-size:100vh` compounds it.

### 6. `--faint` fails contrast in both themes, and it colours every label on every screen — **Critical**

Measured against the mockup's own tokens:

| Pair | Required | Light | Dark |
|---|---|---|---|
| `--faint` on `--panel` | 4.5:1 | **3.14** ✗ | **3.07** ✗ |
| `--faint` on `--paper` | 4.5:1 | **2.91** ✗ | **3.29** ✗ |

`--faint` is the colour of `th` (10.5px, every table column header), `.card>h3` (every card
title), `.pop h3`, `.grp>p` (every rail group label), `.cnt` (9.5px count badges) and `.wave`.
It fails in **both** themes, so there is no "use light mode" escape.

### 7. Icon-only controls take a glyph as their accessible name — **High**

```html
<button class="icon" id="lang" title="English / עברית">א/A</button>
<button class="icon" id="theme" title="Theme">◐</button>
```

Text content wins over `title` in the accessible-name computation, so these are named `א/A` and
`◐`. A screen reader reads the second as "circle with left half black" or nothing. `♥` in the
strip and the `✅`/`⚠️` verdict marks are the same class. `grep -c "<label"` → **0**;
`aria-hidden` appears **0** times.

### 8. Four `<select>` elements have no label of any kind — **High**

`#evsel` on the landing screen, and `#qf`/`#qo`/`#qv` on Ask, which form the sentence
"kind is injection" out of three unlabelled comboboxes. Ask is the screen the spec justifies as
*"filters, for people who do not write SQL"*; unlabelled, it is filters for nobody using a screen
reader.

### 9. No `<h1>`, no accessible name on `<nav>`, no skip link — **High**

`grep -c "<h1"` → **0**. Every screen opens at `<h2>`. `<header>`, `<nav>`, `<main>` and
`<footer>` are all present and correctly mapped (`.app` being a `div` does not break
`banner`/`contentinfo`) — that part is right — but the `<nav>` is unnamed, and there is no skip
link past ten rail buttons to `main`.

### 10. Three chips fail contrast in light mode — **High**

| Chip | Required | Light | Dark |
|---|---|---|---|
| `.chip.gov` (`--gold` on `--goldbg`) | 4.5:1 | **4.31** ✗ | 7.82 ✓ |
| `.chip.ok` (`--ok` on `--okbg`) | 4.5:1 | **4.39** ✗ | 5.66 ✓ |
| `.chip.warn` (`--warn` on `--warnbg`) | 4.5:1 | **4.17** ✗ | 5.69 ✓ |
| `.cnt.x` (`--warn` on `--sink`) | 4.5:1 | **4.06** ✗ | 6.71 ✓ |

All four are near-misses, all in light mode only, all fixable by darkening the foreground two or
three steps. `.chip.crit` passes (5.60 / 4.83).

### 11. The tier dots are colour-alone, and gold vs green measures 1.04:1 — **High**

`.dot.g` (gold, governed) against `.dot.o` (green, jit) is **1.04:1 in light mode, 1.43:1 in
dark**. They are the same luminance. To a dichromat, and on any greyscale printer, the coverage
map's central distinction does not exist. Two things make this worse than usual here:

- The map is the screen whose stated value is *"the gaps are the point"*.
- The spec **requires a real print stylesheet** for this page, and printing is where colour most
  often disappears. The mockup's `@media print` block does not touch `.dot`.

`.dot.w` is correct — it is `background:transparent` with a **dashed** border, a shape difference.
The fix is to make `.g` and `.o` differ in shape the same way.

### 12. `Ctrl+P` from any screen but Coverage prints a blank page — **High**

```css
@media print{ … [data-p]:not([data-p="coverage"]){display:none!important} … }
```

The print block hides every screen except `coverage` and **never removes `coverage`'s `hidden`
attribute**. On the landing screen (Injection preview) the coverage section is `hidden`, so the
print output is empty. The on-screen "Print this page" button lives inside the coverage section
so it happens to work; the keyboard route to printing does not.

### 13. No `prefers-reduced-motion`, and the heartbeat cannot be stopped — **High**

`grep -c "prefers-reduced-motion"` → **0**. The one moving thing is
`setInterval(… h.style.opacity = … , 900)` — an indefinite blink with no pause control. WCAG 2.2.2
requires blinking content lasting more than five seconds to be pausable. It also runs forever in a
background tab.

### 14. No `forced-colors` block — **High**

`grep -c "forced-colors"` → **0**. Under Windows High Contrast every chip background is replaced,
so `gov`/`ok`/`warn`/`crit` collapse into one visual state, as do `.dot.g`/`.o` and the
`aria-current` nav highlight. This is a Windows-first project; the whole audit corpus is
Windows-tested. This is not an exotic mode here.

### 15. Four scrollable regions cannot be focused — **High** (WCAG 2.1.1)

`.cmd code{flex:1;overflow-x:auto;white-space:nowrap}` scrolls a composed shell command that can
be longer than its container; the mockup's own longest is 89 characters
(`mycontext review promote-revision RULE-never-log-customer-email --revision REV-8c21 --yes`). A scroll container
with no focusable content and no `tabindex="0"` cannot be scrolled from the keyboard. The tables
have the same problem the moment they overflow.

### 16. `#ctx` is a mouse-only control — **High**

A `<span>` with a click handler, `cursor:pointer` set from script, and a `title` as its only
affordance. It is demo-only, but it is the pattern the strip will use.

### 17. Focus order puts the popovers after the wrong controls — **High**

DOM order is `header` → `#sesspop` → `#focuspop` → `nav` → `main`. The triggers are inside
`header`, followed by `#lang` and `#theme`. So opening the session picker and pressing Tab reaches
the language and theme buttons before the popover it just opened.

## Keyboard model

### Operability

Every control is a real element: `<button>`, `<a href>`, `<select>`, `<input>`. No `<div onclick>`
(finding 16 is the one to fix). No positive `tabindex` anywhere, ever. Every composite widget —
the tree, the filter group, the two popovers — is **one tab stop with a roving `tabindex`**, so
Tab traverses regions and arrows traverse items. Ten rail buttons are ten tab stops today; that is
acceptable for ten and wrong for a tree of a thousand files, and the tree is the one that must
change.

`:focus-visible` is already styled, and correctly on `:focus-visible` rather than `:focus`. Three
amendments:

1. **Cover `[tabindex]`.** The current selector list is `button, .nav, input, select`; it misses
   every scroll container and every roving-tabindex item.
2. **Change the ring colour.** Gold is the product's *meaning* colour — "this governs" — and using
   it for focus overloads it. A blue ring (`#0b57d0` light / `#8ab4f8` dark) reads as chrome. It
   also removes the 4.15:1-on-sink marginal case.
3. **`outline-offset: 2px` and never `outline: none` without a replacement.** The rail is
   `overflow-y:auto`, which computes `overflow-x` to `auto` too, so a 1px-offset ring on a rail
   button can be clipped at the inline edge.

### Focus management

| Event | Behaviour |
|---|---|
| Screen swap (rail click, `route()`, hash change) | Move focus to the new screen's `<h2>` (`tabindex="-1"`), scroll it into view, and announce the screen name in the polite region. Without the focus move the swap is completely silent to a screen reader and leaves the keyboard user's position on the rail. |
| Popover opens | Move focus to the first row of the listbox. The trigger gets `aria-expanded="true"` and `aria-controls`. |
| Popover closes (Escape, selection, outside click) | Return focus to the trigger. Always. |
| Selection made in the popover | Close, return focus, and announce the new value politely — `"session a3f9c1, last injection 09:22"`. |
| Banner appears (server exited) | Do **not** move focus. `role="alert"` announces without stealing; moving focus on an unsolicited event is the more common failure. Put the banner first in the DOM so its dismiss button is early in the tab order. |
| Tree selection changes | Focus stays on the tree item. The detail panel updates and announces politely; it does not take focus. |
| Copy button pressed | Keep focus on the button. Announce `"copied"` in the polite region rather than by mutating the button's own label — the current 1400ms label swap changes the accessible name of the focused element twice in 1.4 seconds. |

**Escape** closes the innermost dismissible thing and nothing else: popover → banner → nothing.
Escape never navigates, never resets a filter, never leaves a screen. Escape from inside the tree
does nothing, because the tree is not dismissible.

### Skip links

Two, as the first two focusable elements: **Skip to main content** (`#main`, which needs
`tabindex="-1"` or Safari and older Chrome move the indicator without moving focus) and **Skip to
screens** (`#rail`). Visible on focus, positioned with `inset-inline-start` so they mirror.

### The shortcut layer — decided

**A shortcut layer is worth having, and `⌘K` must not be bound.** The previous mockup's sin was
advertising `⌘K` with nothing behind it; the fix is not to bind it, because there is nothing to
bind it *to* — the spec commits to no global search and the regenerated mockup correctly deleted
the search box. Binding a command palette now would recreate the original defect with a handler
attached. `Cmd/Ctrl+K` is also claimed by Firefox (search bar) and by the Chrome/Safari omnibox.

What the tool actually needs is different: it is a **local dev tool kept open on one screen for
long stretches**, where the expensive motion is rail → screen → back. So:

**The layer, precisely.**

- **Off by default, with a toggle**, persisted in `localStorage`. This is what satisfies WCAG
  2.1.4 *Character Key Shortcuts*, whose three acceptable answers are turn-off, remap, or
  active-on-focus-only. Off-by-default is the cheapest of the three and needs no remapping UI.
- **`g` chords for navigation** when enabled: `g` then `p` preview, `c` coverage, `s` simulate,
  `i` injected, `w` work, `k` configure, `a` audit stream, `?` the shortcut sheet. A 1.5-second
  chord timeout, cancelled by Escape.
- **`Escape`, `Tab`, arrows, `Home`/`End`, `Enter`, `Space`** are always live and never
  configurable. `?` opens the shortcut sheet even when the layer is off, so it is discoverable.
- **Never bound:** anything with Ctrl/Cmd + `N T W L D F P S R K + - 0 1-9`; F1–F12; `Insert` and
  `CapsLock` (the NVDA and JAWS modifiers); **`Ctrl+Alt+<letter>` in any form** — on Windows that
  is AltGr, which a Polish, Hungarian or Croatian keyboard uses to type ordinary letters.
- **Single printable keys are bound only inside a focused composite widget**, never globally. The
  tree's type-ahead is legitimate for exactly this reason: a screen reader in browse mode has
  every printable key claimed as a quick-nav key (`H` heading, `T` table, `B` button), and it only
  passes keys through in forms/focus mode — which is where the tree already is.
- **Guard:** ignore the event when `document.activeElement` is an input, textarea, select or
  `contenteditable`, or when `event.isComposing` is true (an IME candidate window owns the
  keystroke).

**The i18n constraint on shortcuts, which is easy to miss.** Use `event.code`, not `event.key`,
for letter shortcuts. On the standard Hebrew layout the physical `G` key produces `ע`, so
`event.key === 'g'` never fires for the Hebrew-first user this spec exists to serve — the shortcut
layer would work in exactly one of the two languages the product ships. `event.code === 'KeyG'` is
layout-independent. Show the *label* from `navigator.keyboard.getLayoutMap()` where available, and
fall back to the Latin letter.

### Zoom, reflow and text scaling — the concrete changes

- Delete `overflow:hidden` from `body`; delete `block-size:100vh` from `.app`. Use
  `min-block-size:100dvh` and let the document scroll.
- The rail collapses below ~52rem into a `<details>` disclosure or a horizontal screen strip
  above `main`. Below that the grid is one column via `grid-template-areas:"rail" "body"`.
- Replace the `.two` media query with `grid-template-columns:repeat(auto-fit,minmax(min(28rem,100%),1fr))`,
  which responds to the *container*, so it survives text-only zoom and the rail collapsing.
- `min-inline-size:0` on every grid and flex child that can contain a table or a `<code>`; the
  `.body` already has it and the cards do not.
- Every table gets an `overflow-x:auto` wrapper with `tabindex="0"`, `role="region"` and
  `aria-labelledby` pointing at its caption.
- All font sizes to `rem`; nothing below `0.75rem`.
- `.banner` leaves `position:fixed` below the reflow breakpoint and becomes in-flow, or it covers
  the footer and part of `main` at 320px.
- Target size (2.5.8): `.icon` is `min-inline-size:29px; block-size:27px` — under the 24×24 CSS px
  minimum only in spacing terms today, but the tree rows at `line-height:1.85` on a 12px font are
  ~22px and become the real failure once they are clickable rows.

## Screen-reader structure

### Landmarks

`banner` / `navigation` / `main` / `contentinfo` already exist and map correctly. Add:

- `aria-label` on the `<nav>` (`"Screens"`), because there will be a second navigation region
  once the detail pane the IA panel proposes exists.
- `aria-labelledby` on `<main>` pointing at the active screen's `<h2>` — so "main region" is
  announced as "main region, Injection preview".
- The status strip is `contentinfo` and should carry `role="status"` on the parts that change
  (`#ctx`), not on the whole strip.

### Headings

One `<h1>` — the product name in the banner, or the active screen title if the banner keeps the
wordmark as an image. Screen titles at `<h2>`, card titles at `<h3>`. The card titles are
currently styled as 12px uppercase micro-labels *and* marked up as `<h3>`, which is right; keep
the markup when finding 28 changes the styling.

### Live regions

Three, and they do different jobs:

| Region | Role | Contents |
|---|---|---|
| Route/action announcer | `role="status"` (`aria-live="polite"`, `aria-atomic="true"`), visually hidden | screen names on swap, "copied", selection changes, filter results counts |
| Audit stream | `role="log"` on the scroll container, plus a **separate** polite `status` for the coalesced count | see below |
| Lifecycle | `role="alert"` | server exited, seen file unreadable, config invalid |

**The streaming audit log, specifically.** A `<table>` is a poor live region — appended rows are
announced without their column context, producing "09:22:41 injection 4 delivered 1 spilled" as
one unstructured utterance, and the user loses the ability to navigate the table by column.
The rule set:

1. **Append, never re-render.** The mockup's `innerHTML = rows.map(…).join('')` is the single
   worst pattern for a live table.
2. The table itself is **not** `aria-live`. It stays navigable.
3. A visually-hidden `role="status"` announces a **coalesced count** on a ≥1.5s timer:
   *"12 new audit records"*. A burst of forty records is one utterance, not forty. Without
   coalescing the queue makes the screen reader unusable for as long as the stream runs.
4. An **"announce every record"** opt-in for users who want the firehose, off by default.
5. A **pause control**, which is WCAG 2.2.2 for the auto-updating content, and which also
   satisfies the "stop the moving thing" need for the heartbeat.
6. `aria-relevant` stays at its default (`additions text`); do not set `aria-relevant="all"`, which
   makes removals announce too and turns log rotation into noise.
7. When rows are trimmed off the top for length, trim **outside** the live region's announcement
   window, or the removal announces.

### Accessible names for the icon-only controls

Every icon-only control gets a real text node in a `.vh` span, and the glyph gets
`aria-hidden="true"`. Not `title`, not `aria-label` on top of visible text (which creates a
name/content mismatch and breaks voice control — WCAG 2.5.3).

| Control | Accessible name | State |
|---|---|---|

### Table semantics

Every data table: a `<caption>` (visible or `.vh`), `<thead>` with `scope="col"` on every header,
`scope="row"` where the first column identifies the row (the Configure budgets table, the Status
counts table). The five headerless tables get real headers — "Item / Tier", "Item / Reason",
"Setting / Value", "Metric / Count", "Topic / What it covers". Numeric columns get
`class="num"` with `text-align:end` and `tabular-nums`; see *Bidi rules* for why that matters more
in Hebrew than in English.

The Work screen's diff table is the one to be careful with: `Field | In force | Proposed` is a
three-column table whose meaning is a *comparison*, and the `stale` chip in the first column
qualifies the row. `scope="row"` on the field name is what lets a screen reader read
"body, stale — In force: changed since this was staged" instead of three disconnected cells.

### The tree

`role="tree"` on the container; `role="treeitem"` on each row; `role="group"` on each child list.
Each item carries `aria-level`, `aria-setsize`, `aria-posinset`, `aria-selected` and — on
branches only — `aria-expanded`. Single-select tree, so `aria-selected` on one item and
`aria-multiselectable` absent.

Keys: `↑`/`↓` move through *visible* items, `→` expands then descends, `←` collapses then
ascends, `Home`/`End` jump, `*` expands all siblings at the current level, `Enter` selects,
printable characters type-ahead. **`→`/`←` swap under RTL** — that is the one place a keyboard
handler has to read `document.documentElement.dir`, and it is easy to forget because the CSS
mirrors for free and the JavaScript does not.

Indentation moves from `&nbsp;` to `padding-inline-start: calc((var(--lvl) - 1) * 1.1rem)` set via
CSSOM. This is simultaneously the a11y fix (depth is `aria-level`, not whitespace), the RTL fix
(non-breaking spaces are *content* and no logical property can mirror them), and the reflow fix.

Tier is a glyph **and** a colour **and** a word in the accessible name: `◆ pinned`, `○ jit`,
`△ not governed`, where the glyph is `aria-hidden` and a `.vh` span carries the word. Working
implementation in the sketch.

### Motion

`prefers-reduced-motion: reduce` must disable: the heartbeat pulse; any stream auto-scroll (which
becomes an instant jump); skeleton shimmers; popover and banner entry transitions; the
`scroll-behavior:smooth` that `$('.body').scrollTop=0` will become. Use
`animation-duration:.01ms` rather than `0s` — a zero duration can skip `animationend`/
`transitionend` and hang a state machine that waits for it.

Independently of the media query: the heartbeat needs a pause control (2.2.2), and the audit
stream needs one anyway (above). One control can serve both — "pause live updates" stops the
stream, the heartbeat and any auto-scroll together, which is also the honest thing to offer, since
what the user wants paused is *the page changing under them*.

`prefers-reduced-transparency` and `prefers-contrast` are worth honouring cheaply: the design has
no transparency except `.bar i.s{opacity:.55}`, which should go opaque under both.

## RTL strategy

The CSS-mechanics table in `04-visual.md` is correct and I am not repeating it; `box-shadow` →
explicit `[dir="rtl"]` override, gradients → a `--grad-dir` custom property, horizontal transforms
→ a `--flip` multiplier, `background-position` percentages → avoid structurally. What follows is
what that table does not reach.

### Things no logical property can express

| Thing | Why | Strategy |
|---|---|---|
| **`&nbsp;` tree indentation** | it is *content*, not style; CSS cannot mirror a character | `padding-inline-start: calc((var(--lvl) - 1) * 1.1rem)`, level set through CSSOM (CSP-safe) |
| **`box-shadow` offsets** | no logical form | already handled for `.nav`; note `--sh` has **no** horizontal offset and needs nothing |
| **SVG interiors** | CSS cannot reach inside a shape; `transform:scaleX(-1)` on the root mirrors the **text** too | mirror the *layout* by recomputing coordinates, or `scaleX(-1)` the root and `scaleX(-1)` each `<text>` back. The ego graph (plan 1 Task 18) is where this lands; there is no SVG in the mockup today (`grep -c "<svg"` → 0) |
| **Directional glyphs in strings** | `→` (U+2192) is **not** in the Unicode bidi-mirrored set, so it does not flip itself — in a Hebrew sentence it keeps pointing right while the text reads right-to-left, i.e. backwards | never put an arrow in prose. `6000 → 8000` is safe **only** because that cell is `class="m"`, so the arrow lives inside an LTR run. In prose use a from/to placeholder pair, or a per-language glyph |
| **`text-transform:uppercase` / `letter-spacing`** | not a mirroring problem — a *language* problem. Hebrew has no case, so the micro-label device silently disappears, and positive tracking damages Hebrew | `:lang(he){text-transform:none;letter-spacing:normal}` plus a weight/size substitute for the lost hierarchy |
| **The `--mono` font stack** | no Hebrew coverage in any listed face | `.m` is LTR-only **by contract**; anything that may contain Hebrew is `<bdi>` in the sans face, not `.m` |
| **The logo `.mark`** | `inset-inline` makes it mirror, and brand marks do not mirror | `inset-inline` → physical `inset`, or draw it symmetrically |
| **Scroll position of an overflowing block** | `scrollLeft` origin differs by engine in RTL | the `.cmd code` element is itself `direction:ltr`, so its scroller is LTR and this does not bite — record it so nobody "fixes" it |
| **`@page` margins** | physical, no logical form | symmetric `16mm`, so it does not matter. Say so, rather than leaving it to be rediscovered |

### The string-table contract

One module per language, flat dotted keys, **no markup in any value**, placeholders named and
never positional.

```js
// strings/en.js
export default {
  "cov.sub": "Every file, coloured by what governs it — through {fn1} and {fn2}, never a bare glob match.",
  "items.one": "{n} item", "items.other": "{n} items"
};
```

**Why named and not positional.** Hebrew reorders the sentence. `%s` and `{0}` bind by position,
so a translation that moves the subject silently swaps two arguments and produces a sentence that
is grammatical, plausible and wrong — the worst possible failure for a tool whose entire claim is
"exactly what Claude gets".

**Why nodes, not strings.** `fill(str, {fn1: code('matchesScope')})` substitutes a *node*, so the
isolation element comes from the renderer and the translator never has to reproduce a `<span>`.
This also removes `innerHTML` from the code path entirely, which closes finding 21.

**Four tests, in the spirit of `test/docs/parity.test.ts` — and, like it, each stating in its
docstring what it cannot check.**

1. **Key parity.** `assert.deepEqual(Object.keys(en).sort(), Object.keys(he).sort())`. Cannot
   check translation freshness — the same caveat §3 already writes for the docs test.
2. **Placeholder parity.** The set of `{name}` tokens in each value is identical across languages.
   This is the one with no analogue in the docs parity test, and it is where real bugs live: a
   Hebrew value that drops `{count}` renders "records." with no number and nobody notices.
3. **No bare technical runs.** A value must not contain `/`, `**`, `--`, `()`, `::`, or an
   `[A-Z]{2,}-` id shape outside a placeholder. This is mechanically checkable and it is exactly
   the rule the current Hebrew table breaks seven times.
4. **Plural completeness, asked of the platform.** For each language, the supplied categories must
   equal `new Intl.PluralRules(lang).resolvedOptions().pluralCategories` — measured:
   `en → ['one','other']`, `he → ['one','two','other']`. Never hard-code `n === 1`.

**Dates, times and numbers — all native `Intl`, no polyfill, zero dependencies.** Three measured
facts that must shape the rules rather than be discovered later:

- `Intl.DateTimeFormat('he-IL',{timeStyle:'medium'})` renders 09:22:41Z as **`9:22:41`** — no
  leading zero, seven characters against English's eight. A `tabular-nums` audit-timestamp column
  goes ragged in Hebrew. Force `{hour:'2-digit',minute:'2-digit',second:'2-digit',hourCycle:'h23'}`.
- The formatter uses the **system** time zone regardless of the locale tag (verified: system
  `Asia/Jerusalem` turned 09:22:41Z into 12:22:41 for both `he-IL` and `en-US`). For a forensic
  audit record that is a silent shift. Pass `timeZone` explicitly and keep the raw ISO value in
  `<time datetime="…">`, which is native, free, and the only copy anyone can paste into a bug
  report.
- **CLDR injects bidi control characters into its own output.**
  `Intl.DateTimeFormat('he-IL',{dateStyle:'full',timeStyle:'long'})` produces a string whose tail
  codepoints are `… 0047 004d 0054 200E 002B 0033 200E` — two **U+200E LEFT-TO-RIGHT MARK**
  characters wrapped around the `+3` offset. Any formatted string that can reach the clipboard
  must be sanitised of `‎‏⁦-⁩`, or an invisible character rides into a shell
  command. See *Bidi rules* for why that is the hard rule here.
- `Intl.NumberFormat` for prose only. Anything inside a `<code>` that will be copied uses
  `String(n)` — `--budget jit=8,000` is a syntax error, and `Intl.NumberFormat('ar-EG')` would
  render it `٨٬٠٠٠`, which is worse.
- `Intl.RelativeTimeFormat('he')` for the session picker's "yesterday", because Hebrew has words
  English does not: `format(-2,'day')` → `שלשום`, a single word for "the day before yesterday".
  A string table cannot express that; the platform can.
- `Intl.ListFormat('he').format(['event','path','seen','restore','focus'])` →
  `event, path, seen, restore ו-focus` — which is, almost exactly, the sentence the mockup's
  `preview.inputs` key hand-writes. Generate it.
- `Intl.Locale('he').getTextInfo().direction` → `'rtl'`. Derive `<html dir>` from this rather than
  storing `dir:'rtl'` in the string table as the mockup does; one source of truth, and a third
  language costs nothing.

## Bidi rules

### The two primitives, and when each applies

| Content | Marker | Why |
|---|---|---|
| Direction **known** LTR — ids, paths, globs, commands, flags, hashes, versions, ports | `.m` / `<code>` with `direction:ltr; unicode-bidi:isolate` | fixes internal order *and* stops the run dragging adjacent neutrals |
| Direction **unknown** — anything read off disk or out of the corpus: item ids, file names, titles, tags, session labels | **`<bdi>`** | `unicode-bidi:isolate` + `dir=auto`; the first strong character decides, and it still cannot leak |
| A **block** of code | `direction:ltr` on the `<pre>`, not on each line | each line becomes independently LTR; without it the block right-aligns and every line's trailing `;` or `{` migrates to the far side |

**`unicode-bidi: plaintext` is the wrong tool here** and is the tempting wrong answer: it
auto-detects per paragraph, so a path whose first segment is Hebrew flips the *whole path* — the
slashes and all following segments — which is a corrupted path, not a mirrored one. `<bdi>` gets
`dir=auto` semantics with an isolation boundary; `plaintext` gets the detection without the
boundary. And `bidi-override` is worse again: it forces visual order, so an identifier renders
backwards.

**Isolation is CSS and elements — never characters.** U+2066 FSI / U+2069 PDI would produce the
same rendering and **must not be used**, because they survive a copy. This product's core
mechanic, stated in the spec and demonstrated on six screens, is *compose a command and copy it
into your own shell*. An invisible U+2066 inside
`mycontext review promote-revision RULE-… --revision REV-8c21 --yes` is a command that fails with
an error naming a character the user cannot see. CSS `unicode-bidi` inserts nothing into the text
node; `<bdi>` inserts nothing into the text node. Both are clipboard-clean. This is also why the
`Intl` output sanitisation above is not pedantry: CLDR puts real U+200E characters in its own
formatted strings, and those *would* be copied.

### What breaks without isolation

All four are properties of the Unicode Bidirectional Algorithm, not of any browser.

1. **Mirrored bracket glyphs, moved to the wrong side.** In `injection()` inside Hebrew prose, the
   `()` are neutrals with a Latin run on one side and Hebrew on the other. Rule N2 gives such a
   sequence the paragraph direction — RTL — so they resolve RTL, their glyphs **mirror**, and they
   render on the *other* side of the identifier. The mockup's `cov.sub` Hebrew string contains
   exactly this. Same class: `(no path — session-start takes none)`.
2. **Trailing punctuation jumping to the far end.** A Latin id ending a Hebrew sentence takes its
   full stop, comma or colon to the left-hand end of the line. `cfg.nowfits`'s
   `…ב‑src/billing/**` puts the `**` in play the same way.
3. **`--` detaching from its flag.** `--yes` at the end of a composed command in prose renders
   with the dashes on the wrong side of `yes`.
4. **A `<pre>` right-aligning line by line.** Without `direction:ltr` on the block, indentation
   flips to the trailing edge and every line's terminator migrates. A Hebrew comment *inside* the
   code still reorders within its own line, which is correct and must not be "fixed".

### What is *not* broken, and must not be "fixed"

Two isolated LTR runs separated by a neutral in an RTL paragraph do **not** render in the wrong
order. An isolate is a single neutral object to the surrounding paragraph, so the runs lay out in
RTL reading order: the logically-first run sits **rightmost**. This looks wrong in a screenshot
and is correct.

This project has already measured it. `2026-08-15-buried-capabilities-ledger.md` records a
suspected RTL defect in `README.he.md` where two `<span dir="ltr">` runs *"looked reordered in a
screenshot"*, resolved by geometry: `src/billing/` (logically first) at x=620 and `invariant`
(logically second) at x=499 on the same line in an `rtl` paragraph — *"which is the correct
order. Reading glyph order out of a screenshot of Hebrew is not evidence; geometry is."* That
sentence is the review rule for this whole area, and it should be quoted into the plan so the next
reviewer does not file the same non-bug.

### Inside tables

- **Column order mirrors, and that is correct.** `At | Kind | What` becomes `What | Kind | At`
  reading right-to-left. No override.
- **Each cell carries its own direction.** A cell holding an id is `.m` or `<bdi>`; a cell holding
  Hebrew prose inherits.
- **Numeric columns need `text-align:end` explicitly.** This is the subtle one. `td.m` sets
  `direction:ltr`, which means `text-align:start` inside that cell now resolves to its **left**,
  while every prose cell in the same RTL table aligns right. A column of token counts hugs the
  wrong edge and the column reads as ragged. `td.num{text-align:end}` fixes it, and it only shows
  up in Hebrew, so it will not be caught by English review.
- **Mixed-content cells need a wrapper.** `body <span class="chip warn">stale</span>` is two LTR
  runs in an RTL cell; without a per-cell `dir="ltr"` on that group, the chip lands to the left of
  the field name and the pairing reads backwards.

### Inside code blocks

- `direction:ltr` on the block element; `unicode-bidi:isolate` so it cannot affect the paragraph
  around it; `overflow-x:auto` on the block with `tabindex="0"` so it is keyboard-scrollable.
- **Never `white-space:normal`** on a command — a wrapped `--revision` is a command that does not
  survive a copy in some terminals.
- **Never break inside an identifier.** `overflow-wrap:anywhere` is acceptable *only* inside a
  scrolling code block; in prose it lets `RULE-never-log-customer-email` split across a line, which
  in an RTL paragraph puts the two halves on different lines in opposite visual positions.
- Syntax highlighting, if it ever arrives, must not wrap tokens in elements that reset direction.

### Numbers

Digits are weak-LTR (`EN`) and mostly behave: `4,260 / 6,000` holds together, because a `/` between
two digit runs is a common separator that takes the digits' direction. The failures are at the
*edges*: a leading sign (`+1`, `-5` — the Configure screen's `<span class="chip ok">+1</span>` is
exactly this shape), a trailing unit or percent adjacent to Hebrew, and a number ending a sentence.
Rule: **any number rendered adjacent to a symbol is isolated**, the same as an identifier. A bare
count in the middle of a Hebrew sentence needs nothing.

## Where mirroring would be wrong

| Element | Mirror? | Why |
|---|---|---|
| **The shell** (rail ↔ body), cards, tables, popover anchoring, nav highlight bar | **Yes** | `grid-template-areas` and the logical properties do it for free; this is already correct |
| **A diff's `-`/`+` gutter** | **No** | The gutter belongs to the *code*, and code is LTR. Mirroring puts the marker on the trailing edge of an LTR line, where it reads as a suffix rather than a marker. The Work screen's per-field diff is the case in hand |
| **A chart's time axis** | **No** | Timestamps are LTR runs and the audit log is read against them. A mirrored axis makes "later" mean "further left" while every label on it reads left-to-right. Keep time running left→right and label the axis in the UI language. (There is no chart today; the Watch strip and any future sparkline are where this lands) |
| **The file tree's indentation** | **No — indent still grows toward the text's own start** | The tree renders paths, which are LTR runs. If the *box* mirrors but the run inside it stays LTR, hierarchy and reading direction disagree and the tree looks inverted. Indent the LTR run from its own inline-start; the surrounding card mirrors normally |
| **Code blocks and any terminal transcript** | **No** | LTR by definition |
| **The logo mark** | **No** | Brand. `.mark::after`'s `inset-inline` currently mirrors it — a bug, not a feature |
| **`.m` runs themselves** | **No** | That is the whole contract |
| **Keyboard shortcut *keys*** | **N/A — but layout matters** | Arrow semantics swap (`→` expands in LTR, collapses in RTL). Letter shortcuts must key on `event.code`, because the Hebrew layout's `G` key emits `ע` |
| **The budget bar** | **Yes, with its label pinned** | It is a quantity, so it fills from the inline-start in both directions. But the `4,260 / 6,000` label under it is an LTR run and stays one; the bar and its legend must agree in order, which means generating both from the same array rather than hard-coding |
| **`✅`/`⚠️` and other status glyphs** | **No** | Not bidi-mirrored characters, and their meaning is not directional |
| **The print stylesheet** | **Follows the UI language** | A printed coverage map is a document a human files. `@page{margin:16mm}` is physical but symmetric, so it needs nothing |

**Two things a Hebrew-first user sees that an English-first user never does.**

The obvious one: the shell is mirrored and every technical term is an LTR island inside RTL prose,
so scanning a sentence is a two-direction task. The consequence for writing, not just for CSS:
keep sentences short, put the identifier at a run boundary rather than mid-clause, and never let
an identifier wrap. The Hebrew UI will read measurably slower than the English one and that is
inherent, not a defect — but prose written *for* it is 20% shorter than prose written for English
and then translated.

The one that will actually get filed as a bug: **a text selection that spans an isolated run looks
discontiguous**. Selecting from Hebrew, through `RULE-never-log-customer-email`, into more Hebrew
highlights three visually separate regions, because the logical range maps to non-adjacent visual
positions. That is the bidi algorithm working. Record it in the plan next to the geometry rule
above, or it will be "fixed" by removing the isolation — which restores every defect in this
section at once.

## Headline

The stylesheet is the best RTL work in the repository — **zero physical properties in 802 lines**,
and the one un-mirrorable `box-shadow` handled the only way it can be — but the isolation it
provides lives in markup that `applyLang()` throws away, so **10 of the 114 Hebrew
strings ship with an unisolated Latin run** while the English build ships with none, which is
precisely backwards.
Everything else divides into two piles: things the mockup never had (**zero** live regions, zero
`<caption>`, zero `scope`, zero `tabindex`, zero `<label>`, zero `<h1>`, no `prefers-reduced-motion`,
no `forced-colors`, a tree whose hierarchy is four non-breaking spaces, and two popovers no
keyboard can reach), and six palette tokens that are near-misses on contrast — of which the one
that matters is `--gold` against `--ok` at **1.04:1**, making the coverage map's central
distinction invisible to a dichromat and identical grey on the printout the spec requires.
Fix the string table to substitute nodes into named placeholders and the isolation, the CSP
compliance, the `innerHTML` trust boundary and the plural contract all close in the same change —
which is why it is first, and why retrofitting it after wave 2 costs five times what it costs now.
