# The test files that predate RULE-a-test-names-the-items-it-rests-on-or-says-it-rests-on-none.
#
# `scripts/check-basis.ts` gates every `test/**/*.test.ts` and `e2e/**/*.spec.ts`
# on carrying a `// @basis` declaration. The 484 files listed here are exempt
# from that ONE requirement — the absence of a declaration — and from nothing
# else: a file listed here that DOES declare a basis has its ids checked like
# any other.
#
# WHY THE EXEMPTION EXISTS. Retrofitting 484 declarations would produce exactly
# the fabrication the rule was written to prevent. Of the 26 fixtures budget/16
# had to repair (commit cdc9fd8), exactly one cited an item and it cited the
# WRONG one — a rule still in force, while the assertion above it rested on the
# rule being reversed. It was the only one that looked responsible and the most
# dangerous in the set. An author asked today what a fixture written months ago
# rested on will guess, and a guess that resolves is worse than silence.
#
# THIS LIST MAY ONLY SHRINK. Delete a line when that file gains a real
# declaration; never add one. A new test file belongs in the gate, not here.
# `test/scripts/basis-gate.test.ts` pins the length below as a CEILING, so a new
# file smuggled in here fails `npm test` as well as review.
#
# It started at 484 and is 473. Nine of the shrink are the files `cdc9fd8` had
# to repair, which now declare what they rest on because that commit's own
# message records it — the one retrofit this project can make without guessing,
# and the evidence that the convention expresses the set it was designed from.
# The other two are `test/core/summary.test.ts` and `test/ingest/schema.test.ts`,
# declared when SUMMARY_MAX_CHARS moved from 160 to 250 (owner ruling 2026-09-08).
