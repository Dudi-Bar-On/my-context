# לראות אילו קבצים ואזורים המאגר שלך באמת מכסה

כל פקודה וכל בלוק פלט בעמוד הזה הורצו מול סביבת עבודה נקייה בזמן הכתיבה. אין כאן
שום דבר להמחשה בלבד.

**נבדק על:** my_context v1.0.2, <span dir="ltr">Node 24, Windows 11</span>.

הערה על הכותרות: ארבע הכותרות הנדרשות מופיעות כאן באנגלית לצד העברית, מפני שבדיקת
הקיום של המוצר מחפשת בדיוק את המחרוזות האנגליות. הטקסט עצמו מתורגם, לא מסוכם.

## What it is for — למה זה נועד

היקף הוא בקרת העלות המרכזית במוצר הזה, וההרגל האחד שמכריע אם הוא עובד בכלל. פריט
עם `scope: ["src/billing/**"]` נשקל רק על קבצים תחת `src/billing/`. פריט **ללא**
היקף נשקל על *כל* פעולת קובץ, לתמיד.

כיסוי הוא החצי השני של אותה שאלה: בהינתן ההיקפים שכתבת, אילו חלקים במאגר הקוד
באמת נשלטים, ואיזה מהם הוא פער שאיש לא הסתכל בו?

## How it works — איך זה עובד

**היקף הוא רשימת globs בסגנון POSIX על הפריט.** ההתאמה מנרמלת את שני הצדדים, כך
שנתיב Windows ו-glob בסגנון POSIX מסכימים ביניהם. היקף ריק פירושו בלתי מוגבל.

**`scopePolicy` מכריע מה "אין היקף" אומר, לכל קטגוריה.** יש לו שלושה ערכים:
`global` (ברירת המחדל — בלתי מוגבל, תואם לכל נתיב), `required` (תיעוד בלי היקף
נדחה), ו-`inert` (פריט חסר היקף תואם **לשום** קובץ ולא לכולם). קבע את האחרון
ופריט חסר היקף בקטגוריה הזו מפסיק לשלוט בכל דבר:

```json
{
  "profile": "standard",
  "categories": {
    "requirement": { "scopePolicy": "inert" }
  }
}
```

אותו מאגר, אותה שאילתה, לפני ואחרי. לפני:

```console
$ mycontext search --path src/api/handler.ts
┌───────────────────────────────────────────────────────┬─────────────┬────────┐
│ id                                                    │ type        │ status │
├───────────────────────────────────────────────────────┼─────────────┼────────┤
│ LESSON-the-3ds-sandbox-declines-valid-cards-at-random │ lesson      │ active │
│ LESSON-the-sandbox-declines-3ds-cards-at-random       │ lesson      │ active │
│ REF-architecture-overview                             │ reference   │ active │
│ REQ-checkout-completes-in-two-steps                   │ requirement │ active │
│ RULE-every-price-is-an-integer-of-minor-units         │ rule        │ active │
│ TODO-check-whether-the-3ds-retry-path-double-charges  │ todo        │ active │
└───────────────────────────────────────────────────────┴─────────────┴────────┘
```

אחרי:

```console
$ mycontext search --path src/api/handler.ts
┌───────────────────────────────────────────────────────┬───────────┬────────┐
│ id                                                    │ type      │ status │
├───────────────────────────────────────────────────────┼───────────┼────────┤
│ LESSON-the-3ds-sandbox-declines-valid-cards-at-random │ lesson    │ active │
│ LESSON-the-sandbox-declines-3ds-cards-at-random       │ lesson    │ active │
│ REF-architecture-overview                             │ reference │ active │
│ RULE-every-price-is-an-integer-of-minor-units         │ rule      │ active │
│ TODO-check-whether-the-3ds-retry-path-double-charges  │ todo      │ active │
└───────────────────────────────────────────────────────┴───────────┴────────┘
```

`REQ-checkout-completes-in-two-steps` חסר ההיקף נעלם — לא נמחק, פשוט אינרטי. הוא
שורד כשורת אינדקס ותו לא.

**השתמש בזה כשקטגוריה היא בעיקר שאיפתית** — דרישות ושאלות פתוחות הן כאלה לא פעם —
ואתה רוצה שחבריה ישלטו רק במקום שאליו הופנו במפורש. זה כלי חד: פריט ש*שכחת* לתת
לו היקף מפסיק לשלוט בשקט.

**פריט מוצמד פטור מהשאלה.** פריט `always: true` שולט בכל נתיב מעצם הגדרתו, ולכן
צביעה שלו לפי תיקייה הייתה גורמת לתיקייה נשלטת להיראות כפער. הכיסוי מרים את
הפריטים המוצמדים החוצה ומצהיר עליהם פעם אחת, וזה מה שגורם למילה "פער" לומר משהו.

## From the CLI — מהשורה

חיפוש הנתיב הוא תשובת הכיסוי של הטרמינל, נתיב אחד בכל פעם:

```console
$ mycontext search --path src/billing/charge.ts
┌─────────────────────────────────────────────────┬────────────┬────────┐
│ id                                              │ type       │ status │
├─────────────────────────────────────────────────┼────────────┼────────┤
│ CONST-card-numbers-never-reach-the-logs         │ constraint │ active │
│ LESSON-the-sandbox-declines-3ds-cards-at-random │ lesson     │ active │
│ RULE-every-price-is-an-integer-of-minor-units   │ rule       │ active │
└─────────────────────────────────────────────────┴────────────┴────────┘
```

`status` נודניק לגבי הסך הכולל, בכל פעם שאתה מריץ אותו:

```
usage: no sessions recorded yet — decay reporting starts once items begin to be injected.
  1 active normative item(s) carry no scope, so they apply to every file and compete for the jit
  budget on every file operation.
```

`doctor` מוצא את הכשל האחר — glob של היקף שאינו תואם לדבר, מפני שהתיקייה שנקב
בשמה שונתה או הוסרה — ומדווח עליו כממצא במקום לתקן אותו.

כדי לקבוע או לשנות היקף:

```bash
mycontext add rule "..." --scope "src/billing/**" --summary "..." --yes
mycontext edit <id> --scope "src/billing/**,src/payments/**"
```

**מה שהשורה יודעת לעשות כאן והממשק לא.** לענות על "מה שולט בנתיב המדויק הזה"
כרשימה שאפשר להעביר ב-pipe, עם `--json`. וגם לכתוב `scopePolicy` לתוך
`config.json` ביד — למסך ההגדרות של הדפדפן יש רצועת מדיניות היקף, אבל הקובץ הוא
שלך.

## From the UI — מהממשק

מסך **כיסוי היקף** (`nav.inj`) הוא המסך של היכולת הזו, ופסק הדין שלו הוא *מה
מכסה כל תיקייה, ומה לא*.

הוא עץ של כל נתיב שנסרק, צבוע לפי מה ששולט בו, עם חלונית פירוט לצידו. שורת המצב
שלו היא כל התמונה במשפט אחד: <span dir="ltr">`{covered} / {total} files covered · {gaps} gaps ·
{catEmpty} / {catTotal} categories empty`</span>.

ארבעה דברים שהוא עושה ורשימה אינה יכולה:

- **צבע הוא סדר גודל, לא רק מצב.** הפס של כל שורה מציג נשלט, בלתי נשלט ולא נבדק
  כפרופורציות, עם הספירה לצידן — נקודות לבדן לא היו יכולות לומר *כמה* כהה שורה
  הייתה.
- **פריטים מוצמדים מורמים** לרצועה משלהם בראש, ומוצהרים פעם אחת.
- **"לא נבדק" הוא צבע רביעי**, נבדל מ"פער". תיקייה שאיש לא סרק אינה תיקייה שאיש
  אינו שולט בה.
- **קטגוריות שאין בהן דבר** מופיעות ברשימה, וכשאין כאלה הוא אומר זאת כמדידה:
  *"אין — נמדד, כל קטגוריה מחזיקה לפחות פריט אחד"*, לעולם לא כשטח ריק.

על מאגר שעדיין אינו שולט בדבר, הוא אומר זאת פעם אחת — *"עדיין שום דבר אינו שולט
בפרויקט הזה"*, עם ההערה שזה המצב הרגיל לסביבת עבודה חדשה — במקום לצייר קיר של
אזהרות, אחת לכל שורה.

**מה שהממשק יודע לעשות כאן והשורה לא.** להציג כיסוי כמפה. אין פקודת טרמינל שסורקת
את העץ וצובעת אותו; `search --path` עונה על נתיב אחד, וזה עונה על כולם בבת אחת.

**מה שהממשק אינו יכול לעשות כאן.** לשנות היקף. העץ הוא קריאה; עריכת ההיקף של פריט
מורכבת במסך מרכיב הפקודות או במסך התיעוד ומאושרת לפני שהיא רצה, ו-`scopePolicy`
חי ב-`config.json`.
