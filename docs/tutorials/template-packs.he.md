# להתחיל פרויקט חדש מחבילת תבנית

כל פקודה וכל בלוק פלט בעמוד הזה הורצו מול סביבת עבודה נקייה בזמן הכתיבה. אין כאן
שום דבר להמחשה בלבד.

**נבדק על:** my_context v1.0.2, ‏Node 24, ‏Windows 11.

הערה על הכותרות: ארבע הכותרות הנדרשות מופיעות כאן באנגלית לצד העברית, מפני שבדיקת
הקיום של המוצר מחפשת בדיוק את המחרוזות האנגליות. הטקסט עצמו מתורגם, לא מסוכם.

## What it is for — למה זה נועד

סביבת עבודה חדשה לגמרי אינה שולטת בדבר. עבור פרויקט בתחום שמישהו כבר חשב עליו —
ענף מפוקח, מסגרת עבודה מסוימת, סגנון בית — להתחיל מדעה עדיף על להתחיל מריק.

חבילת תבנית היא מאגר שנכתב מראש ומישהו פרסם, שמייבאים כך שכבר לסשן הראשון שלך יהיה
מה לומר.

## How it works — איך זה עובד

**כל פריט שחבילה מכניסה מגיע כ‑`draft`.** שני המסלולים לתוך סביבת עבודה —
‏`mycontext init --pack <path>` ו‑`mycontext pack import <path>` — נוחתים באותה
דרך, ו**אין דגל `--trust`**: גבול שדגל יכול לעקוף אינו גבול. אתה מקדם את מה שאתה
רוצה; השאר לעולם אינו שולט.

**חבילה נושאת ידע תחומי, ולעולם לא הגדרה שמתארת אותך.** היא רשאית לשאת פריטים
והגדרות קטגוריה. היא אינה רשאית לשאת את התקציבים שלך או את מבנה מאגר הקוד שלך,
מפני שמחברה אינו יכול לראות אף אחד מהם.

**שלמות, מתוארת במדויק.** לחבילה יש digest מלא לכל קובץ, ממוין, ומחרוזת גרסה
שהמחבר סיפק בזמן האריזה — תיאורית, מפני שאין כתובת git שאפשר לגזור ממנה אחת. הגילוי
הוא רשימה מנוהלת בתיעוד: אין רישום, אין שליפה חוזרת, אין בדיקת גרסה ברשת. עדכון
פירושו ייבוא נוסף, ושלושת סלי ההתנגשות מראים לך מה השתנה.

**מה שה‑digest אינו מוכיח**, ונאמר בפשטות מפני שזה הדבר שהכי קל לקרוא בו יותר
מדי: ‏checksum מוכיח שהקבצים הגיעו שלמים. הוא אינו אומר דבר על השאלה אם המחבר ראוי
לאמון, והוא לעולם אינו שולט בהפעלה.

**הייבוא ממיין כל פריט נכנס לשלושה סלים** — חדש, אותו מזהה עם תוכן שונה, וזהה —
ושום דבר אינו מוחל בלי אישור.

## From the CLI — מהשורה

```console
$ mycontext pack list
my_context: no packs have been imported into this workspace. `mycontext pack import <path>` reads
one, and `mycontext export --as-pack` writes one.
```

```bash
mycontext init --pack ./packs/regulated-industry   # התחל סביבת עבודה מאחת
mycontext pack import ./packs/regulated-industry   # הוסף אחת לסביבת עבודה קיימת
mycontext pack list                                # מה יובא לכאן
mycontext export --out ./out --as-pack             # כתוב אחת משלך
```

אחרי ייבוא, הטיוטות נמצאות בתור הסקירה הרגיל:

```bash
mycontext review
mycontext review promote <id> --scope "src/**" --yes
```

**אין פקודת slash לחבילות.** ייבוא מאגר של מישהו אחר הוא מעשה מכוון בטרמינל, לא
משהו שעושים באמצע סשן.

**מתוך סוכן**, ‏`preview_pack_import` קורא מוצר ומדווח מה ייבוא שלו *היה* עושה. אין
כלי שמבצע את הייבוא.

**מה שהשורה יודעת לעשות כאן והממשק לא.** את הכול. ייבוא, הצגת רשימה וכתיבה של
חבילה הם מעשי טרמינל; הדפדפן קורא את מה שכבר כאן.

## From the UI — מהממשק

מסך **חבילות תבנית** (‏`nav.ch`) הוא ארבעה כרטיסי הסבר ועוד החצי שהמוקאפ לא יכול
היה לצייר: החבילות שנמצאות בפועל בסביבת העבודה ה*זו*, מצורפות למאגר כפי שהוא
עכשיו. בלי הצירוף הזה הוא היה מסך הסבר עם כפתור העתקה, והמודל שמאחורי נקודת הקצה
אומר זאת.

ארבעת הכרטיסים הם ארבע העובדות שלמעלה, כל אחת מצוירת כטבלה קטנה ולא כפרוזה: איפה
פריט מיובא נוחת ולמה, מה חבילה רשאית ואינה רשאית לשאת, סיפור השלמות עם ההסתייגות
שלו לצידו, ושלושת סלי הייבוא.

השם והגרסה של חבילה הם מחרוזות שמישהו אחר כתב, ולכן המסך מצייר אותן כטקסט שאינו
מהימן — מוצג, לעולם לא מפורש.

**מה שהממשק יודע לעשות כאן והשורה לא.** להציג את סיפור האמון של החבילות ואת
החבילות שייבאת במסך אחד, כך ש"מה החבילה ההיא הכניסה לכאן" היא הסתכלות ולא שאילתה.

**מה שהממשק אינו יכול לעשות כאן.** לייבא חבילה, לכתוב אחת, או לקדם את הטיוטות של
חבילה מהמסך הזה. ‏`pack` אינו בקטלוג הפקודות כלל; המסך מסתיים בשורה שאתה מדביק,
והטיוטות מוכרעות במסך תור הסקירה.
