# לדמות תקציב לפני שמתחייבים אליו

כל פקודה וכל בלוק פלט בעמוד הזה הורצו מול סביבת עבודה נקייה בזמן הכתיבה. אין כאן
שום דבר להמחשה בלבד.

**נבדק על:** my_context v1.0.2, <span dir="ltr">Node 24, Windows 11</span>.

הערה על הכותרות: ארבע הכותרות הנדרשות מופיעות כאן באנגלית לצד העברית, מפני שבדיקת
הקיום של המוצר מחפשת בדיוק את המחרוזות האנגליות. הטקסט עצמו מתורגם, לא מסוכם.

## What it is for — למה זה נועד

לכל שכבת הזרקה יש תקציב טוקנים. הגדל אחד ויגיע יותר, במחיר שנגבה מכל סשן שמשלם על
השכבה הזו. הקטן אחד ומשהו יפסיק להגיע — אבל לא בהכרח הדבר שציפית לו.

היכולת הזו היא הדרך לגלות מה, לפני שאתה כותב את המספר לתוך `config.json`.

## How it works — איך זה עובד

**חמישה תקציבים, ואלה ברירות המחדל שנשלחות:**

| שכבה | ברירת מחדל | נגבה |
|---|---:|---|
| `restored` | 8000 | אחרי כיווץ |
| `pinned` | 6000 | בכל תחילת סשן |
| `jit` | 6000 | בנגיעה בקובץ תואם |
| `continuity` | 2000 | אחרי כיווץ, עבור טקסט מסירה |
| `index` | 1200 | בכל תחילת סשן |

`continuity` הוא בכוונה תקציב הטקסט המלא הקטן ביותר, והגלישה שלו רועשת ולא נבלעת:
פריט שאינו נכנס בו נקוב בשם בתצוגה המקדימה, בבלוק המוזרק וכממצא אבחון.

**פריט שאינו נכנס נשפך בשלמותו.** שום דבר לעולם אינו נקטע, והשפיכה מוצהרת לפי
מזהה.

**הבורר הוא first-fit, וזה החלק הלא אינטואיטיבי.** `fitToBudget` ממשיך לנסות
פריטים מאוחרים יותר אחרי שאחד לא נכנס, ולכן תקציב *גדול יותר* יכול להכניס פריט
גדול אחד מוקדם ולדחוק החוצה שניים קטנים. הגדלת תקציב יכולה אפוא **לפלוט** פריט.
"נשפך" אינו דירוג עדיפויות, והמוצר אומר זאת בכל מקום שבו הוא מצייר שפיכה.

**התקציבים מתחברים.** תחילת סשן משלמת <span dir="ltr">`pinned` + `index`</span>; נגיעה בקובץ משלמת
`jit`; כיווץ משלם <span dir="ltr">`restored` + `continuity`</span>.

## From the CLI — מהשורה

תקציבים הם הגדרה, ולכן הטרמינל מגיע אליהם כמו לכל הגדרה אחרת —
<span dir="ltr">`.my_context/config.json`</span>, תחת `budgets`:

```json
{
  "profile": "standard",
  "budgets": { "pinned": 4000 }
}
```

כל מפתח הוא רשות וכל מפתח שתשמיט שומר על ברירת המחדל שלו. שגיאת הקלדה לעולם אינה
מתקבלת ונזרקת בשקט. שם שכבה שאינו אחד מהחמישה **נדחה** בתוך הבלוק — הוא נוקב
בעצמו בשגיאה, לצד החמישה שההגדרה הזו מקבלת, ושום דבר אינו נטען. שגיאת כתיב בשם
המקטע עצמו, <span dir="ltr">`"budget"`</span> במקום `"budgets"`, היא מפתח ברמה העליונה: היא **מדולגת
ומוצהרת** ולא נקראת, כך שהתקציבים נשארים בברירות המחדל שלהם ואומרים לך איזה מפתח
לא נקרא.

הגדל את תקציב pinned רק אם יש לך סיבה: הוא נגבה מכל סשן לנצח. היקף מספק את אותו
ידע בדיוק כשהוא רלוונטי, בחינם.

החשבון מופיע לפני כל כתיבה שעלולה לשנות אותו. `mycontext refresh` על reference
מדפיס את שינוי הגודל ואת התקציב שהפריט מתחרה בו לפני שהוא שואל:

```console
$ mycontext refresh REF-architecture-overview
about to refresh:
  item        REF-architecture-overview
  type        reference
  source      docs/ARCHITECTURE.md
  checksum    11464bc9a02d1351 -> e308f1fc47813cde
  size        3 -> 3 line(s), ~16 -> ~18 estimated tokens
  budget      this category is on the rationale tier, so the item is never injected in full and costs the injection budget nothing. It is stored, searchable, and counted in the session index. Retiering the category to "normative" in config changes that — and changes what governs this project — see README, "reference".
  the item's title, observations, relations, scope and tags are untouched; only the
  body is replaced, whole, by the file's current text.

my_context: refusing without confirmation — stdin is not interactive. Rerun with --yes to confirm, or run this from an interactive terminal.
```

העבר את הקטגוריה הזו לשכבת `normative` ואותה שורה עצמה תשתנה ותנקוב בתקציב הטקסט
המלא הגדול ביותר שהפריט מתחרה בו מעכשיו.

`mycontext audit --items --role spilled` הוא התשובה שבדיעבד: אילו פריטים
התקציבים באמת הפילו.

**מה שהשורה יודעת לעשות כאן והממשק לא.** שום דבר שהדפדפן אינו יכול להגיע אליו גם
הוא — אבל הטרמינל הוא המקום היחיד שבו אפשר לקבוע `budgets` ביד, שכבה אחר שכבה,
בקובץ שאפשר לעשות לו diff ולסקור אותו.

## From the UI — מהממשק

**סימולטור התקציב** (`nav.inj`) הוא המסך שהיכולת הזו עוסקת בו באמת. פסק הדין שלו
הוא *כל חמש השכבות*, וכותרת המשנה שלו מציגה את המלכודת מראש: *"גרור תקציב וראה מה
נכנס. הגדלה שלו יכולה לפלוט פריט — הבורר הוא first-fit, לא קו חיתוך מדורג."*

מה שהוא מצייר:

- **שורה לכל שכבה** — תקציב, נכנסים, נשפכים — שבה "נכנסים" הוא **יחס** ולא ספירה:
  *"{fits} of {eligible}"*, כך שתקציב מלא ומאגר ריק אינם יכולים להיראות אותו דבר.
- **מדרגות הקבלה** — הפריטים שהתקבלו בכל ערך תקציב. הסריקה **מדויקת, לא נדגמת**:
  הבורר רץ מחדש בכל עלות מצטברת של מועמד, ולכן שום דבר בין שתי מדרגות אינו מומצא.
  מדרגה אדומה היא פליטה.
- **בקרת טווח**, שקובעת עד כמה רחוק המחוון חוקר. זהו חסם שהסימולטור מחזיק בעצמו,
  לא תקציב — שום דבר במסך הזה אינו כותב ל-`config.json`.
- **רשימת השפיכה, מפוצלת לשתיים**: פריטים ש*כבר בהקשר* (הסוכן מחזיק אותם; הוצאת
  תקציב השכבה הזו עליהם לא הייתה משנה דבר) ופריטים *שנעדרים באמת* (מעולם לא נמסרו
  בסשן הזה — הגדלת התקציב היא מה שבאמת היה משנה את מה שמגיע). הפיצול הזה הוא ההבדל
  בין תקציב שקטן מדי ובין תקציב שמוצא פעמיים.

הוא עונה על שתי שאלות ומסמן איזו מהן אתה קורא: השאלה ה**קרה** — מה חלון חדש לגמרי
היה מקבל מהמאגר הזה ומהתקציבים האלה — ושאלת הסשן, מה הסשן הנבחר היה מקבל עכשיו עם
קבוצת ה-seen שנמסרה לו.

מסך **ההגדרות** הוא המקום שבו מספר מדומה הופך לאמיתי, והוא הכתיבה האחת שהשרת מבצע
*בעצמו* ולא בהרצת פקודת שורה: תקציבים, מאחורי אישור, כאשר `config.json` נקרא מחדש
בזמן הכתיבה כדי ששינוי שנעשה בינתיים במקום אחר לא יידרס. בדיוק המאפיין `budgets`
מוחלף; שאר הקובץ נשאר כמו שהיה.

**מה שהממשק יודע לעשות כאן והשורה לא.** את כל מה שלמעלה. אין פקודת טרמינל שסורקת
תקציב, ואין שום דרך בטרמינל לראות בכלל את מדרגת הפליטה.

**מה שהממשק אינו יכול לעשות כאן.** לשנות כל הגדרה שאינה תקציבים. `profile`, שכבות
קטגוריה, `scopePolicy` ו-`watchedDocs` מורכבים עבורך להרצה או נערכים בקובץ;
הסימולטור עצמו אינו כותב דבר כלל.
