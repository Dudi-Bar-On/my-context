# למצוא את הפריט שאתה חושב עליו, מהשורה או מהממשק

כל פקודה וכל בלוק פלט בעמוד הזה הורצו מול סביבת עבודה נקייה בזמן הכתיבה. אין כאן
שום דבר להמחשה בלבד.

**נבדק על:** my_context v1.0.2, <span dir="ltr">Node 24, Windows 11</span>.

הערה על הכותרות: ארבע הכותרות הנדרשות מופיעות כאן באנגלית לצד העברית, מפני שבדיקת
הקיום של המוצר מחפשת בדיוק את המחרוזות האנגליות. הטקסט עצמו מתורגם, לא מסוכם.

## What it is for — למה זה נועד

מאגר שאי אפשר לחפש בו הוא מאגר שמפסיקים לסמוך עליו. היכולת הזו היא צד הקריאה של
my_context: רשימת מה שיש כאן, מציאת הפריט האחד שאתה זוכר בחצי אוזן, הדפסתו במלואו,
וכשהשאלה חדה יותר מחיפוש מילים — הרצת SQL לקריאה בלבד מעל האינדקס.

זו גם הדרך לענות על השאלה ש-`CLAUDE.md` מעולם לא ידע לענות עליה: *מה שולט בקובץ
הזה?*

## How it works — איך זה עובד

קובצי ה-Markdown הם האמת. לצידם יושב אינדקס SQLite נגזר, שנבנה מחדש מה-Markdown
לפי דרישה ובטוח למחיקה — <span dir="ltr">`.my_context/.gitignore`</span> מחריג בדיוק את הקובץ הזה ואת
כלום מלבדו.

יש ארבע שאלות שונות, וארבע קריאות שונות:

- **`list`** — הכול, או הכול בקטגוריה אחת, כטבלה.
- **`show`** — פריט אחד, שלם, בדיוק כפי שהוא על הדיסק.
- **`search`** — לפי טקסט, סוג, תגית, **נתיב**, סטטוס, וקשר. צורת הנתיב היא זו
  שעונה על "מה שולט בקובץ הזה?": היא מריצה את אותה התאמת היקף שההזרקה מריצה.
- **`query`** — SQL לקריאה בלבד מעל האינדקס, מוגבל ל-1000 שורות.

**יומן הביקורת** הוא קריאה חמישית, מעל דבר אחר לגמרי: לא מה שהמאגר מחזיק, אלא מה
שהמוצר עשה. יש לו מדריך משלו, *לצפות במה ש-my_context עושה, בזמן אמת*.

## From the CLI — מהשורה

```console
$ mycontext list
┌─────────────────────────────────────────────────┬────────────┬────────┐
│ id                                              │ type       │ status │
├─────────────────────────────────────────────────┼────────────┼────────┤
│ CONST-card-numbers-never-reach-the-logs         │ constraint │ active │
│ LESSON-the-sandbox-declines-3ds-cards-at-random │ lesson     │ active │
│ RULE-every-price-is-an-integer-of-minor-units   │ rule       │ active │
└─────────────────────────────────────────────────┴────────────┴────────┘
```

חיפוש טקסט:

```console
$ mycontext search 3ds
┌─────────────────────────────────────────────────┬────────┬────────┐
│ id                                              │ type   │ status │
├─────────────────────────────────────────────────┼────────┼────────┤
│ LESSON-the-sandbox-declines-3ds-cards-at-random │ lesson │ active │
└─────────────────────────────────────────────────┴────────┴────────┘
```

חיפוש לפי נתיב — "מה שולט ב-`src/billing/charge.ts`?":

```console
$ mycontext search --path src/billing/charge.ts
┌─────────────────────────────────────────────────┬────────────┬────────┐
│ id                                              │ type       │ status │
├─────────────────────────────────────────────────┼────────────┼────────┤
│ CONST-card-numbers-never-reach-the-logs         │ constraint │ active │
│ LESSON-the-sandbox-declines-3ds-cards-at-random │ lesson     │ active │
│ RULE-every-price-is-an-integer-of-minor-units   │ rule       │ active │
└─────────────────────────────────────────────────┴────────────┴────────┘
```

קרא את התשובה בעיון: היא מפרטת מה **תואם** את הנתיב, לא מה יוזרק. השיעור תואם
מפני שהתאמת היקף היא תכונה של הפריט, והכלל תואם מפני שאין לו היקף כלל. מה שבאמת
מגיע לסשן היא שאלה צרה יותר, שעליה עונה *לראות מה my_context באמת הזריק, ולמה*.

SQL, כשהשאלה היא צורה ולא מילה:

```console
$ mycontext query "SELECT id,type FROM items WHERE type='rule'"
┌───────────────────────────────────────────────┬──────┐
│ id                                            │ type │
├───────────────────────────────────────────────┼──────┤
│ RULE-every-price-is-an-integer-of-minor-units │ rule │
└───────────────────────────────────────────────┴──────┘

1 row(s)
```

כל פקודת קריאה מקבלת `--full`, `--short`, `--summary` ו-`--json`, כך שאותה שאילתה
היא טבלה עבורך ומסמך עבור סקריפט.

**פקודות ה-slash.** <span dir="ltr">`/mycontext:search`, `/mycontext:query`, `/mycontext:show`,
`/mycontext:audit`</span>, ופקודת `/mycontext:list-<category>` לכל אחת מ-29 הקטגוריות —
פקודת רשימה לכל קטגוריה קיימת כדי שסשן יוכל לבקש שכבת ידע אחת בלי להרכיב דגל.

**מתוך סוכן**, אותן קריאות הן כלי ה-<span dir="ltr">MCP `query_items`, `get_item`, `list_items`</span>
ו-`list_todos`.

**מה שהשורה יודעת לעשות כאן והממשק לא.** לכתוב SQL משלך. מסך השאילתה מרכיב את
המשפט בשרת מפרמטרים קשורים וצורות מוכנות; שום טקסט שאילתה אינו חוצה את החוט.
`mycontext query` הוא המשטח היחיד שבו ה-SELECT הוא שלך. גם `--json` בכל פקודת
קריאה קיים רק בשורה, וכך גם `search --relation`, <span dir="ltr">`--linked-to`</span> ו-`--direction`.

## From the UI — מהממשק

מסך **שאילתה** (`nav.ev`) הוא משטח הקריאה של הדפדפן: שורת סינון אחת, ארבע
שאילתות מוכנות, טבלת תוצאות בת שלוש עמודות, ו — וזה החלק שכדאי להכיר — חלונית
שמראה את **ה-SQL שהשרת באמת הריץ** עבור התשובה שמולך. המסך מראה לך את המשפט; הוא
לעולם אינו שולח לך אחד.

לצידו, מסך **מצב** עונה על "מה יש כאן" כספירות, ו-`GET /api/item/:id` שמאחורי
תצוגות הפריט מדפיס פריט אחד שלם.

**מה שהממשק יודע לעשות כאן והשורה לא.** להראות לך את המשפט ואת השורות יחד, ולאפשר
לך לעבור מתוצאה ישירות אל תצוגת הקשרים, ההזרקה או האבחון של אותו פריט בלי להקליד
מזהה מחדש.

**מה שהממשק אינו יכול לעשות כאן.** לקבל SQL חופשי, בכלל. הוא גם אינו יכול להגיש
לך תוצאה כ-JSON: הדפדפן מצייר שורות, ו-`--json` נשאר תשובה של טרמינל.
