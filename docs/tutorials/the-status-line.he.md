# להציג את מצב my_context בשורת המצב של הטרמינל שלך

כל פקודה וכל בלוק פלט בעמוד הזה הורצו מול סביבת עבודה נקייה בזמן הכתיבה. אין כאן
שום דבר להמחשה בלבד.

**נבדק על:** my_context v1.0.2, <span dir="ltr">Node 24, Windows 11</span>.

הערה על הכותרות: ארבע הכותרות הנדרשות מופיעות כאן באנגלית לצד העברית, מפני שבדיקת
הקיום של המוצר מחפשת בדיוק את המחרוזות האנגליות. הטקסט עצמו מתורגם, לא מסוכם.

## What it is for — למה זה נועד

<span dir="ltr">Claude Code</span> מצייר שורת מצב בכל הודעת עוזר. היכולת הזו מכניסה לתוכה את המצב של
my_context עצמו — כמה מחלון ההקשר המאגר הזה אחראי לו, איזה מיקוד בתוקף, מה הייתה
הפעולה המבוקרת האחרונה — כך שהתשובה נמצאת מולך ולא במרחק פקודה.

היא עושה גם דבר שני, בשקט ובתועלת: היא מפצלת את המטען לדיסק כדי שממשק הרשת יוכל
לצרף את נתון ההקשר האמיתי ליומן הביקורת.

## How it works — איך זה עובד

**<span dir="ltr">Claude Code</span> מזרים מטען JSON לפקודת ה-`statusLine` המוגדרת בכל הודעת עוזר.**
`mycontext statusline` קורא את המטען הזה מ-stdin ועושה איתו שני דברים:

1. **מפצל אותו בשלמותו** לקובץ לכל סשן, כך שממשק הרשת יוכל לצרף את מספר ההקשר
   ליומן הביקורת לפי `session_id`.
2. **מדפיס שורה אחת** ש-Claude Code יציג.

**זו הצטרפות מרצון, ומותקנת במכוון.** `mycontext statusline install` מדפיס את
הגדרת ה-`statusLine` הקיימת שלך ואת מה שהוא היה שם במקומה, ואינו כותב דבר בלי
`--yes`. אם כבר יש לך שורת מצב, המתקין *מאציל* אליה במקום להחליף אותה, כך ששורתך
שלך ממשיכה לעבוד.

**הפיצול הוא פקודת שורה שאתה מתקין, לא נקודת קצה של הממשק**, וזו הנקודה: הדפדפן
לעולם אינו כותב את הקובץ הזה — `mycontext statusline`, שרץ מהגדרות Claude Code
שלך, כן. גם הממשק אינו נטול כתיבה, אבל הכתיבות שלו הן קבוצה נקובה ומוכרעת —
תקציבים במסך ההגדרות, שורות הביקורת שנכתבות סביב הרצה מאושרת של מרכיב הפקודות,
וניהול הפנקסים של השרת עצמו — וכל נתיב קריאה בו עדיין קורא בלבד.

**כשל מאובחן בשורה, לא בקוד היציאה.** שגיאה שנזרקת או יציאה שאינה אפס היו גורמות
לשורת המצב של Claude Code להבהב או להיעלם בין הודעות, ולכן כל ענף שיש לו מטען יוצא
עם 0 ואומר מה השתבש *בשורה עצמה*. היציאה היחידה שאינה אפס היא המקרה שבו אין מטען
כלל — כלומר שאדם הריץ את הפועל ביד.

הרץ אותו כך והוא יאמר לך זאת:

```console
$ mycontext statusline
my_context: `mycontext statusline` expects Claude Code's status-line JSON on stdin. It is installed as a statusLine command by `mycontext statusline install`, which prints your existing setting and what it would replace it with, and writes nothing without --yes.
```

## From the CLI — מהשורה

```bash
mycontext statusline install [--yes]     # הדפס את ההגדרה הנוכחית, והתקן
mycontext statusline uninstall [--yes]   # החזר את מה שהיה שם
mycontext statusline                     # הפקודה ש-Claude Code מריץ; מצפה ל-JSON ב-stdin
```

את השורה עצמה אפשר לרנדר רגילה או כ-powerline, והיא תשתמש בצבע רק במקום שבו
הטרמינל אומר שצבע מותר. מה שהיא יכולה לשאת, בהתאם למה שזמין: את ענף ה-git, את
החלק מחלון ההקשר ש-my_context אחראי לו, את מספר ההזרקות וכמה מהן אינן רשומות, את
המיקוד הפעיל מתואר במילים, ואת הפעולה המבוקרת האחרונה.

**אין פקודת slash**, ואין כלי MCP. התקנת שורת מצב היא שינוי בהגדרות Claude Code
*שלך*, לא במאגר של הפרויקט.

**מה שהשורה יודעת לעשות כאן והממשק לא.** את הכול. `statusline` אינו בקטלוג
הפקודות של הדפדפן ואין לו מסך.

## From the UI — מהממשק

**לשורת המצב אין מסך — אבל היא הסיבה שמספר אחד במסכים אחרים הוא אמיתי.**

בלי הפיצול, לממשק הרשת אין גישה לנתון ההקשר של Claude Code עצמו: הוא יכול לספור
מה my_context הכניס לסשן, והוא אינו יכול לדעת איזה חלק מהחלון זה. עם שורת מצב
מותקנת, הנתון הזה מגיע לממשק דרך הקובץ המפוצל ומצורף ליומן הביקורת לפי מזהה הסשן.

לכן הניסוח הישר של הקשר הוא: **התקן את היכולת הזו בטרמינל, ומספרי חלק ההקשר של
הדפדפן מפסיקים להיות לא נמדדים.** במקום שבו הפיצול נעדר, הממשק אומר שהנתון אינו
נמדד במקום לנחש אחד.

**מה שהממשק יודע לעשות כאן והשורה לא.** להשתמש במספר. שורת המצב מראה לך את החלק
של סשן אחד בזמן שהוא קורה; הממשק מצרף אותו ליומן, כך שאפשר לשאול על אילו פריטים
החלק הזה באמת הוצא.

**מה שהממשק אינו יכול לעשות כאן.** להתקין, להסיר, להגדיר או לרנדר שורת מצב. הוא רק
קורא את מה שהפיצול השאיר מאחור.
