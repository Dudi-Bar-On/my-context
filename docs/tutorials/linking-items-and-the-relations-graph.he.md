# לקשר שני פריטים, ולראות איך המאגר שלך מתחבר

כל פקודה וכל בלוק פלט בעמוד הזה הורצו מול סביבת עבודה נקייה בזמן הכתיבה. אין כאן
שום דבר להמחשה בלבד.

**נבדק על:** my_context v1.0.2, <span dir="ltr">Node 24, Windows 11</span>.

הערה על הכותרות: ארבע הכותרות הנדרשות מופיעות כאן באנגלית לצד העברית, מפני שבדיקת
הקיום של המוצר מחפשת בדיוק את המחרוזות האנגליות. הטקסט עצמו מתורגם, לא מסוכם.

## What it is for — למה זה נועד

כלל שיצא משיעור, אילוץ שמגביל דרישה, שאלה פתוחה שחוסמת משימה — אלה עובדות על
המאגר שלך ששום כמות של חיפוש טקסט מלא לא תשחזר אחרי ששכחת אותן.

קשרים רושמים אותן, פעם אחת, באוצר מילים סגור, כך שהחיבור שורד את מי שיצר אותו.

## How it works — איך זה עובד

**שמונה־עשר סוגי קשר, והרשימה סגורה**: <span dir="ltr">`derived_from`, `constrains`,
`supersedes`, `blocks`, `mitigates`, `refines`, `relates_to`, `links_to`,
`depends_on`, `caused_by`, `conflicts_with`, `amends`, `produced`,
`discovered_by`, `unblocks`, `enforces`, `enforced_by`, `answers`</span>.

`mycontext help workflow` מדפיס את הטבלה של מה כל אחד מהם אומר, מרונדרת מאותו
אוצר מילים שהכלי מקבל — כך שהעזרה והרשימה אינן יכולות לסתור זו את זו.

**`superseded_by` אינו אחד מהם, בכוונה.** הוא טוען שינוי מחזור חיים ולא קשר,
והוצאתו מאוצר המילים *היא* השער שמונע את זיופו. `mycontext supersede` כותב את שני
הכיוונים שלו יחד כך שהם אינם יכולים להיפרד; `link` מסרב לכתוב אותו כלל.

**קשרים מסווגים כנושאי משקל או כהתייחסותיים**, וההבדל חשוב בשני מקומות. מיקוד
שמסתיר קצה אחד של קשר *נושא משקל* מוצהר כקשת תלויה באוויר, מפני שהקורא נשאר פועל
לפי הוראה חלקית. `relates_to` תלוי באוויר נקרא כרעש; `constrains` תלוי באוויר
נקרא כאזעקה.

**קשר נשמר על הפריט, ב-Markdown שלו**, ולכן הוא נוסע עם הייצוא, עושה diff ב-pull
request, ונבנה מחדש לתוך האינדקס במקום להישמר בו בלבד.

## From the CLI — מהשורה

```console
$ mycontext link RULE-every-price-is-an-integer-of-minor-units refines CONST-card-numbers-never-reach-the-logs
my_context: RULE-every-price-is-an-integer-of-minor-units refines CONST-card-numbers-never-reach-the-logs.
```

קריאת הגרף בחזרה היא `search`, וזה החלק שכדאי להכיר:

```console
$ mycontext search --linked-to CONST-card-numbers-never-reach-the-logs
┌───────────────────────────────────────────────┬──────┬────────┐
│ id                                            │ type │ status │
├───────────────────────────────────────────────┼──────┼────────┤
│ RULE-every-price-is-an-integer-of-minor-units │ rule │ active │
└───────────────────────────────────────────────┴──────┴────────┘
```

```bash
mycontext search --relation refines            # כל פריט עם קשר מסוג אחד
mycontext search --linked-to <id>              # מה מצביע על הפריט הזה
mycontext search --linked-to <id> --direction out   # או על מה הוא מצביע
mycontext edit <id> --unlink <relation> <id>   # הסר אחד
mycontext focus --relations                    # הסוגים שאפשר לבנות עליהם מיקוד
```

**פקודות ה-slash.** <span dir="ltr">`/mycontext:link`</span> ו-`/mycontext:unlink`.

**מתוך סוכן**, `link_items` כותב אחד — ומסרב ל-`supersedes`, שהיא העבודה של
`supersede_item`.

**מה שהשורה יודעת לעשות כאן והממשק לא.** לכתוב קשר, או להסיר אחד. לא `link` ולא
`edit --unlink` נמצאים בקטלוג הפקודות של הדפדפן, ולכן שניהם מעשי טרמינל. גם
`search --relation`, <span dir="ltr">`--linked-to`</span> ו-`--direction` קיימים כדגלים בשורה בלבד.

## From the UI — מהממשק

מסך **קשרים** (`nav.ev`) מצייר *גרף אגו, לא פקעת*: פריט אחד במוקד, רדיוס 1,
בפריסה שכבתית דטרמיניסטית, עם תקרה קשיחה של 60 צמתים ו"עוד N" מפורש כשהתקרה
נוגסת. בלי פיזיקה, ובלי ספריית גרפים.

**הכיוון הוא הפריסה.** העמודה שפריט יושב בה מכריעה לאן הקשר מצביע, ולכן אין צורך
לדמות דבר. כל קשת מציגה את סוג הקשר שלה; סגנון הקו מציג את החומרה, לפי אותו סיווג
של נושאי משקל שגילוי המיקוד משתמש בו.

**הצמתים נושאים מזהים, לא כותרות**, וזה מה שמשאיר טקסט דו-כיווני מחוץ ל-SVG.

מסנן הסוגים הוא בקרה, והמסך זהיר לגבי ההבדל בין עובדה על הבקרה ובין עובדה על
המאגר: *"אין קשר מהסוגים שהשארת"* מדבר על הפריט הזה ומתבטל בבחירת פריט אחר, בעוד
*"לא נבחר שום סוג קשר, ולכן אין מה לצייר — כאן או בכל פריט אחר"* נכון בכל מקום
ומתבטל רק בלחיצה על **הכול**. פריטים שאין להם קשר מסוג שהושאר מוסתרים עם ספירה
ועם בקרת "הצג אותם בכל זאת", במקום להיות מצוירים כשדה של צמתים בודדים.

**מה שהממשק יודע לעשות כאן והשורה לא.** לצייר את זה. `search --linked-to` עונה על
קפיצה אחת מפריט אחד כרשימה; זה מציג את השכונה, עם כיוון, סוג וחומרה גלויים כולם
בבת אחת.

**מה שהממשק אינו יכול לעשות כאן.** ליצור או למחוק קשר. הגרף הוא קריאה, מקצה לקצה.
