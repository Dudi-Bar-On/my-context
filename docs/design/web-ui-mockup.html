Why not — the first gate that failed

The gates in select()'s own order — eligible, tier, focus, scope, seen, budget — because the order is the explanation: a list of six reasons is noise, and the one that binds is only meaningful in the position it holds. Rungs above it passed, the rung itself carries the diagnosis, and everything below is not reached rather than passed. Composing the fix needs a stable code on injection(); today the five causes differ only in English prose.

Why raising a budget can remove an item
fitToBudget is first-fit: it keeps trying later items after one does not fit. A larger budget admits a large item early, which can then crowd out two small ones that previously both fitted. "Spilled" is not a suffix of a priority list.

A readOnly:true connection still permits VACUUM INTO '<any path>', which writes a full copy of the database wherever the statement says. A keyword scan is what stops it, and that scan cannot see keywords inside backtick or bracket identifiers. Removing the input removes the problem.

Decay

✅ a chart, not a table — of sessions

Items not injected in the last N sessions. The unit is sessions, not weeks: the ledger holds one row per (session, item, tier) and a repeat injection inside one session collides, so what it stores is a set of first-injections, not an event stream — and an axis against a clock would be wrong here even where it would look better. The delivery history in the second card is a different measurement from a different source.

Recency comb — one tooth per item, never bucketed

warm cold never injected — a kind, not a big number pinned and cold — a defect signal, not decay ∀unrestricted — a breadth view over cold ∪ warm, never a third bucket

What "cold" does and does not mean
The ledger records injection, not reading or reliance. A cold item may still be governing — and a cold always:true item is a bug in selection, not decay.

90-day delivery, per item — delivered against spilled

One cell per day. Intensity is how much was delivered that day, a hatched cell is a day the item was spilled, and an empty cell is a day nothing happened — six quiet weeks are six weeks of empty cells and need no reading. This is the one view that separates "quiet" from "selected and thrown away repeatedly". Its source is not the ledger, which records deliveries only: it is audit_item.role joined to audit.at, both indexed, with the since / until filters that already ship.

Relations

✅ an ego-graph, not a hairball

One focused item, radius 1, deterministic layered layout, hard cap of 60 nodes with an explicit "+N more". No physics, no dependency.

focus target not in corpus superseded load-bearing referential dangling

Nodes carry ids, not titles — which keeps bidi-sensitive text out of every SVG in the product. Every edge carries its relation type and its line style carries severity, because those are two different facts: isLoadBearing already classifies the vocabulary, so a dangling relates_to reads as noise and a dangling constrains reads as an alarm. Procedures

PROPOSED

An ordered set of steps performed once and then done — as against a rule, which is one instruction that applies every time. A rule is a single instruction; a procedure is a sequence. Decided; nothing implements it yet.

Four states, and exactly one of them injects

StateMeaningInjection
proposedwritten, not approved. An agent may author one herenot injected
readyyou approved itindex line only
activeyou initiated itin full, every session
donecompletednot injected

Injecting only in active is the mechanism, not a sentence asking the model to wait. A procedure the model holds in full is one it may begin following, so it is delivered only in the state you put it in deliberately. The failure this guards against is not the obvious one: it is a procedure left active forever, injecting in full long after the work finished.

PROC-migrate-money-columns-to-integer-cents

active 3 / 5 steps

[x]Add the integer column beside the decimal one
[x]Backfill, and verify the two agree on every row
[x]Switch reads to the integer column
[ ]Switch writes, behind the flag
[ ]Drop the decimal column

Steps are a ## Steps section in the Markdown, parsed the way ## Observations already is. "3 of 5" is counted, never stored — there is no second place a procedure could disagree with itself.

Who may tick a box

mycontext procedure step may flip one checkbox, matched by a strict pattern, and may reach no other byte of the item. It does not go through the draft gate.

That is a distinction, not an exemption. The gate exists to stop an agent changing normative content; a checkbox is progress. Every flip is audited, so the relaxation is visible rather than quiet.

What is not relaxed: the state. active → done stays yours. Ticking the last box does not close the procedure — it lets the agent ask. An agent that can mark its own procedure done can declare victory.

mycontext procedure done PROC-migrate-money-columns-to-integer-cents

Abandoned rather than finished is superseded — the existing status already means exactly that, and a fifth spelling of one idea is the defect this project has paid for four times.

Template packs

PROPOSED

A pre-authored corpus someone published — "the regulated-industry flavour" — imported at init to start from an opinion instead of an empty directory.

Where it lands, and why that differs

init --packdraft
pack importdraft

Both routes land the same way, and it is draft — there is one importer behind them, and it writes every item a pack brings in as a proposal. Choosing a pack at init looks like the act of trust, but an empty corpus is exactly where an unreviewed opinion is hardest to notice, so the import asks rather than assumes. There is no --trust flag; a boundary a flag can override is not a boundary.

What a pack may carry

items/**travels
category configurationtravels
budgetsnever
watchedDocsnever

The line, once: a pack carries what its author knows about the domain; never a setting that describes you — your context budget or your repository layout. The author cannot see either.

Integrity, described accurately

Digestsha256, full, per file, sorted
Versiondescriptive, supplied by the author when packing — there is no git address to derive one from
Discoverya curated list in the docs. No registry, no re-fetch, no version check over the network
Updatingimport again; the three buckets show what changed

What the digest does not prove. A checksum a pack carries about itself is transit integrity — the files arrived intact. It is not evidence the author is trustworthy, and it never gates activation. The item checksum field is a 16-hex truncation for drift detection and is a different thing entirely; a pack manifest does not reuse it.

mycontext init --pack ../packs/regulated-industry
